# 节假日数据来源（原地 ADR）

`data/chinese-days.json` 不是手写数据，来自社区包 [`chinese-days`](https://github.com/vsme/chinese-days)。

## 来源与许可

- 包：`chinese-days`
- 版本：`1.5.10`
- 上游文件：`https://cdn.jsdelivr.net/npm/chinese-days@1.5.10/dist/chinese-days.json`
- 许可：MIT（允许再分发与修改；本文件保留来源与版本）
- 抓取日：2026-11-14（覆盖 2004–2027 年，共 648 个法定节假日日期）

## 为什么只保留 `holidays`

上游文件有三张表：`holidays`（法定节假日）、`workdays`（调休上班日）、`inLieuDays`
（调休占用的周末）。本插件的判定口径（计划 §2）是：

- 法定节假日 → 全天谷；
- 周六日 → 全天谷，**调休上班的周六日仍按谷**；
- 其余工作日 → 只有峰段窗口内为峰。

按这个口径，`workdays` 与 `inLieuDays` 永不参与判定。只保留 `holidays` 让数据文件的
审阅面与仓库体积都保持最小，也避免「有意不用却仍随包分发」的歧义。值的英文名与天数
字段同样削掉，只留中文短名（用于拒绝文本里的「法定节假日（X）」）。

## 刷新

节假日安排每年由国务院办公厅公布，上游通常在公布后几天内更新。数据过期不会让判定
出错，只会让未知年份按 `unknownYear` 保守处理（默认按峰），因此刷新是年度人工动作：

```powershell
# 在插件目录执行；版本号省略时沿用脚本内默认值
node scripts/refresh-holidays.mjs 1.5.10
```

脚本会重新抓取上游、重算中文短名、按日期升序覆盖本文件并打印条目数。刷新后跑一次
`node --test` 确认判定矩阵仍然全绿，并在 PR/提交说明里写明新的覆盖年份。

## 已知边界

- 2028 年及以后未被覆盖：未知年份按 `unknownYear`（默认 `peak`）处理并告警。
- 上游把调休上班日记在 `workdays`；本插件刻意不读，见上。
