# L.l1 harnessing 摩擦反思（tb-5 返工第 3 轮）

## 摩擦反思

本轮最大摩擦不在组员执行力，而在**真源数据自身的错误会顺着机制放大**：deck-spec
占位↔槽位错位绑定（p8 整页循环错绑、p5/p9/p10 标签张冠李戴）使 audit 对错件判 √，
组员照 spec 执行反而出错（p9 引用编号被误反转、w8 把正确件当多余件删掉）——「机械
对账」的可信度完全取决于 spec 汇编时的读数纪律，而这一点此前没有流程约束（V5 只约束
了任务书断言，没约束 spec 汇编）。其次是**注记保鲜无机制**：修复完成后槽级 note 仍留
「待换/判 ✗」旧措辞，rv2/rv3 两轮复审都因纯 prose 过期判 B，挤牙膏式清了三轮。第三是
**换序类指令的靶态歧义**（p9/p10 各一次）：批语文本「左中右变成右中左」可作两种解读，
只有「现状机械读数＋草稿占位唯一真源」双锚定才能钉死方向——R2 p10 净零对换的教训在
R3 险些复发，靠组长目检占位图才拦住。工具面上 audit 缺位置/顺序/引用编号判据、
verify 渲染目录自动发现误扫，也各消耗了一轮。

## 改进清单

| # | 摩擦 | 立单方向 | 预期收益 |

| 1 | spec 汇编占位↔槽位错绑未被约束（V5 只管任务书），错件被 audit 判 √ | spec 汇编工序固化「逐槽目检/机械绑定＋note 附读数来源」入预设 06 §4L；audit 加占位指纹一致性校验（placeholder.md5 与 slot 语义配对、循环错位检测） | 真源错误在汇编期暴露，不再放大到组员执行 |
