# L.l2 改进拆解派单（tb-5 开题PPT制作）

## 拆解

依据 L.l1 摩擦反思（`data/taskbooks/tb-20261018-212705-ppt.l1-摩擦反思.md`）的 4 项改进
清单，拆解为 devops 可一次性实施的工单。四项同属 orch CLI/钩子工具面，彼此正交、可同批
实施；按「一项一验收」给出验收判据。

**工单 1：路由卡片状态失真修复（最高优先）**
- 现象：`plan advance --task` 入队后，[NEXT]/watch 路由卡片的「动作」栏仍显示「书写本
  环节任务书并派发」指向已入队环节，且长期滞后在首个环节（实测全程卡片停在
  G1.P1.w1）；头部「（无关联任务书）」与 `taskbooks link` 已完成状态不符。
- 修法：卡片生成逻辑改取工作清单真实状态——在途环节显示「等待完成事件」，「派发」动作
  只出现在真可派发环节；taskbook 关联状态从 taskbooks/plan 关联记录回显。
- 验收：派发任一环节后抓取下一次卡片输出，动作栏≠「派发」该在途环节；link 后头部不再
  显示「无关联任务书」。

**工单 2：`suggestions show <id>` 入口**
- 现象：审批需带判决包理由，但 CLI 无法看建议正文，只能 cat state 文件。
- 修法：`pysci-orch suggestions show <id>`（输出 kind/正文/证据/success_criteria；
  已审批的从 approved/rejected 目录同样可查）；或 `suggestions list --full`。
- 验收：`suggestions show` 对未审批与已审批 id 均输出完整正文；无 id 时报用法。

**工单 3：`bench seen` 多 id**
- 现象：传多 id 报 unrecognized arguments，且未说明单收。
- 修法：`bench seen <id>...`（nargs='+'）逐项标记；或维持单收但错误信息注明「一次一个」。
- 验收：一条命令标记多项成功；错误路径有明确用法提示。

**工单 4：state 面自动提交扩展**
- 现象：交付留档有「新留档即提交」自动钩子，但 plan/建议/回复等 state 变更需组长每轮
  手动 chore(state) 提交以防 merge_dirty_face 拦组员合并（本轮手动 7 次）。
- 修法（择一，实施者定）：①自动提交钩子覆盖面扩到 orchestration/state 全域（沿用
  「新留档即提交」口径）；②提供 `pysci-orch state-commit` 一键提交该目录。
- 验收：模拟 plan/建议文件变更后，无需手动 git 操作即不脏（或一键命令一步清账）；既有
  自动提交行为不回归。

**派单口径**：四项均交 devops 一并实施（同批一份任务书即可，各带回归测试）；工单 1 优先。
无成员侧行为变更，不涉规则文件裁决。空改进清单情形不适用（本轮有 4 项）。
