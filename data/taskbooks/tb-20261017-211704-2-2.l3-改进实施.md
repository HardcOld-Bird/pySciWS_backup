## 工作包 A：orch CLI 引导一致性（`src/pysci/skills/orchestration/tools/`）

1. **F1 环节规格可回看**：`plan advance --dry`（或等价查询入口）在环节已入队/待证据状态
   下仍可回打「粗描述 + evidence 标题段 + 收尾命令」。evidence 标题段以
   `ROLE_EVIDENCE_SECTIONS`（plans.py:93）为**单一真源**打印，禁双份维护。
2. **F3 `status --brief`**：`pysci-orch status --brief` 一页输出——计划进度（x/y＋当前
   环节）、成员队列在途计数、事件水位、大任务队首；≤30 行。
3. **F4 引导文案口径统一**：规格打印/引导中的收尾命令一律裸 `pysci-orch …`
   （basic.md §3「首选裸命令」）；删除 `uv run --no-sync pysci-orch` 前缀引导。
4. **F5 `plan reassign --step` 双形态**：短 yaml id（`b2`）与显示名（`B.b2`）皆接受；
   或最小改法＝报错文案注明「--step 用显示名（如 B.b2）」（二选一，取成本低者）。

## 工作包 B：docx 标注机械核验器（`src/pysci/skills/document_writing/tools/`）

5. **F2 `pysci-compose docx marks <docx> [--para <关键词>]`**：抽取 run 级标注
   （strike / highlight / shd 底色 / bold / color），按段输出「标注类型+颜色+文本片段」；
   `--para` 按段文本关键词过滤。抽取面＝`w:strike`、`w:shd w:fill="FF0000|FFFF00"`、
   `w:b`（实测惯用面）。输出可人读可 grep（writing 自检 6/reviewer G10 的机械对照）。
