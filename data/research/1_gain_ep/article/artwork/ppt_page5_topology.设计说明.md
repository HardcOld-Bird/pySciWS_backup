# ppt_page5_topology 设计说明

**用途**：汇报 PPT 页 5 的整页单主题大图（16:9，2816×1584，一页全屏放这一张）。与页 4
（`ppt_page4_trend.png`）成套：同一浅灰白底 + 深蓝 `#1F4E79` + 橙 `#D55E00` 两色系、扁平矢量、
细线、大留白。

## 拓扑元素与真实体系的对应（依据 `orchestration/README.md` §1）

图自左至右一条指挥链 + 一组星形扇出，对应 README §1 的**星形拓扑**「组长（TUI 主会话）派发 →
headless 组员」：

1. **用户 → TUI 控制台 → 组长**：对应 §1「组长（TUI 主会话）」与 §10 端到端工作流——用户只在
   TUI 投递大任务（终端窗口内只画灰色占位线条，不出现任何真实代码，避免伪码字形），组长经
   `pysci-orch` 派发；链条用橙色箭头自上而下串起。
2. **组长 → 编排系统**：对应 §3.3 派发「三入口（`dispatch`/`plan`/`queues`）统一走成员 FIFO
   队列」——编排系统是派发的枢纽节点，图中以橙色描边圆形表示，是画面中唯一一条橙色主箭头。
3. **编排系统 → 两个分组框**：右侧两组装在浅灰圆角框里的成员卡片，按 README §1 的「13 席 = 7
   专职 ＋ 6 特殊」分组概括——
   - **专职组员（7）**：仿真 sim、绘图 figure（本图作者即 drawing，同属专职席）、写作 writing、
     理论 theory、文献 lit、作画 drawing、建模 model3d；深蓝实心卡片，白色两字标签；
   - **特殊席位（6）**：副手 deputy、审查 reviewer、基建 devops、压测 bencher、偏好 twin、
     巡检 inspector；浅橙填充、橙色描边卡片。图中标签为投影可读的**二字简称**，不展开职务全称。
4. **队列意象**：每张成员卡片左侧紧贴一个「三个竖直浅灰小方块 + 橙色小箭头指向卡片」的图形，
   对应 §3.3 与 §8「每个成员一条 FIFO 队列」，任务是排队进入成员而非直接调用；「每席一条
   FIFO 队列」提示行只作一次图例说明。
5. **标题「一个组长 · 十三席组员 · 各一条队列」**：一句话点题——一个组长（不做末端工作，§1）、
   十三席组员、每席一条队列。**面向非专业听众，图内不出现 orch 命令、state.json 等机制细节**。

## 规格与配方

- 尺寸 2816×1584（精确 16:9）；模型 `doubao-seedream-5-0-pro-260628`（即梦 5.0 Pro）文生图；
  prompt 全文见 LEDGER（`runs/ppt_p5_{a,b,c}.json`）与 PNG 内嵌 `pysci:prompt`。任务书要求
  `.png`，5.0 档只出 jpeg，故经 `imagine adjust` 免费转格式（`--out` 落在 `data/` 内）。
- **计费 3 张**（候选 A/B/C，均归档于 `data/skills/ai_drawing/gallery/ppt_p5_{a,b,c}.jpg`）；
  交付首选 **B**：
  - A 版面最饱满，但第二组被画出 **7 张卡片且「偏好」重复**（成员名出错，违反文字准确性红线），
    且连线交叉成网；
  - **B**：7+6 全部正确无重复、零乱码，连线干净少交叉、队列图形逐席可见——综合最优；
  - C：为了放大队列图形、修正引线而重发，结果反而**只在每组首张卡片前画出队列**，削弱了
    「每席一条队列」的要素，故仅归档不交付。
- 每张组员卡片的二字标签与 README §1 的成员一一对应，为本页与真实体系的唯一映射表（见上 §3）。
