## G2① · 机制性视觉检查闸（机械面）

- **新模块** `src/pysci/skills/document_writing/tools/slides_visual.py`：
  - `render_pptx_pages()`：固化 **pptx → pdf → 逐页 PNG** 链（LibreOffice + pymupdf），
    产出 `<deck>_render/page-NNN.png`；
  - `verify_pptx_render()`：只读已落盘渲染图，校验**渲染存在 / 页数 = 幻灯片数 / 非空白页**。
- **新命令** `src/pysci/skills/document_writing/tools/compose.py`：
  - `compose slides render <pptx> [--out DIR] [--dpi 140]`——产渲染图（交付附件）；
  - `compose slides verify <pptx> [--render-dir DIR] [--min-ink 0.002]`——视觉验收闸，
    三态任一不过 **退出码非 0**。
- **check 注册** `orchestration/state/registry.json` 的 `checks` 新增 `pptx-visual`：
  `uv run --no-sync pysci-compose slides verify {path}`——交付声明
  `<artifact check="pptx-visual">…deck.pptx</artifact>` 即由 orch 自动验收，缺渲染/页数不符即 FAIL。
- **回归测试**：
  - `tests/skills/document_writing/test_slides_verify.py`——三态（齐备 PASS / 缺渲染 FAIL /
    页数不符 FAIL）+ 空白页 FAIL + CLI 退出码 + 真渲染链（无 LibreOffice 时跳过）；
  - `tests/skills/orchestration/test_checks_pptx_visual.py`——随附 registry 含 `pptx-visual`
    且 cmd 形状正确、run_checks 把产物路径喂 `{path}` 并据退出码判 pass/fail。

### 验收命令实测

```
$ compose slides render '…/20260918/20260918.pptx' --out /tmp/pptx-render-smoke
[slides render] 20260918.pptx：5 页 → 渲染 5 张 PNG 于 C:\…\Temp\pptx-render-smoke
（page-001.png … page-005.png，共 5 张；已 Read page-002.png 确认版式真实、非空白）

$ compose slides verify '…/20260918/20260918.pptx'          # 约定目录无渲染
[slides verify] FAIL 20260918.pptx：幻灯片 5 页 / 渲染 0 张（…/20260918_render）
    ✗ 缺渲染：未找到逐页渲染 PNG（…/20260918_render）——先跑 `compose slides render` 并在交付中附上
rc=1

$ compose slides verify '…/20260918/20260918.pptx' --render-dir /tmp/pptx-render-smoke
[slides verify] PASS 20260918.pptx：幻灯片 5 页 / 渲染 5 张（C:\…\pptx-render-smoke）
rc=0

$ uv run --no-sync pytest tests/skills/document_writing/test_slides_verify.py \
      tests/skills/orchestration/test_checks_pptx_visual.py -q

```
