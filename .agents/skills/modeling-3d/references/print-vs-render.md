# 打印件与渲染件不混原则（⑥域红线之二）

⑥域同时产出两类几何，**语义、判据、失败模式全不同**，全链不混：

| 维度 | 打印件（print） | 渲染件（render） |
|---|---|---|
| 目的 | 物理制造（切片→打印） | 视觉传达（概念图/示意图/参考） |
| 几何语义 | 实体：闭合流形、法线朝外、实壁厚 | 表面：开面/单面/非流形**合法** |
| 尺寸 | 精确 mm，必须断言 | 任意尺度（构图需要优先） |
| 精度诉求 | 尺寸>美观 | 美观>尺寸 |
| 导出 | STL（+OBJ 备查）；GLB 无单位语义不作打印交付 | GLB/OBJ/PNG |
| 验收判据 | `judge_print`（严） | `judge_render`（宽） |
| 典型失败 | 切片废件、装配不上、内外反 | 渲染卡死、黑斑、构图不对 |
| 失败处置 | 回 bpy 脚本改几何 | 回 scene 脚本改材质/布光/减面 |

## 三条硬规则

1. **渲染件不直接打印**。Tripo 云网格、渲图用的摆件、展示 GLB 一律**不可**进切片器：
   非流形、任意缩放、无壁厚概念。需要打印的形状，以渲染件作**视觉参照**回 bpy
   重新参数化建模，再走打印判据过门。
2. **打印件不为渲染妥协几何**。打印 STL 就是打印 STL——不要为了渲图好看往打印脚本里
   加倒角假缝、贴图浮雕；渲染想要的观感在 scene 脚本的材质/灯光层实现。
   同一几何两用途时：part 脚本出 STL 过打印门，scene 脚本**导入该 STL** 再渲染
   （工作流 A→B 的顺序就是这个原因）。
3. **判据不互换**。渲染件不跑 `judge_print`（会误杀合法开面），打印件不跑
   `judge_render`（会放过废件）。`judge_*` 的 `criteria` 字段写死各管各的。

## 为什么这条红线单列

旧域教训：mesh 建模器（Blender）没有尺寸约束系统，"能渲"和"能打"是两种正确性——
混用的后果不是丑，是**静默废件**（非流形 STL 切片器或拒或产废品，尺寸差 5% 的夹具
装不上实验台）。分开判据 + 冻结回脚本，是把"两种正确性"各自钉死在自己的链上。

## 与③域渲染边界的关系

概念渲染**管线**留⑥（3D 资产→出图连贯）；渲染**成品图**交给③域时只交 PNG 媒体，
尺寸/DPI/背景按③排版契约。pyvista 快速预览（看形状、查网格）归③，不算⑥交付。
