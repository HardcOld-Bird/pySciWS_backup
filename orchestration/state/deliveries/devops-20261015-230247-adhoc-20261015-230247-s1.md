## 逐项：根因（实测复现）→ 修法

### ① 驳回批语只存首行
**根因**（实测）：面板里批语控件是单行 `Input(id="tb-note")` —— 实测 `type(app.query_one("#tb-note")).__name__ == "Input"`，回车即触发提交、输入框容不下换行。
**修法**：改**多行 `TextArea`**（CSS `height: 5` + `overflow-y: auto` + `scrollbar-gutter: stable`，与详情栏多行/滚动同族）；复位与读取改 `.text`。

### ② 状态显示过期
**根因（与其初判略有出入，以实测为准）**：TUI 的列表行与详情页**本来就是实时读** state.json（实测 delivered 后列表 `[◆ delivered]`、详情 `- 状态：delivered`）——真正过期的是**交付物快照** `data/taskbooks/<id>.report.md`：实测「active 时生成 → transition 到 delivered 后，文件里仍写 `- 状态：active`」。它正是 §4.3 #5 定义的 delivered 交付物，组长批复时读它就会读到旧口径。
**修法**：在 `taskbooks.transition()`（**唯一收口**，`sync_delivered`/`accept`/`reject` 皆经它）于**终态**（delivered/accepted/rejected/failed）重建报告——**仅在快照已存在时**重建（不凭空造文件）、写失败 fail-soft 不阻塞迁移。口径因此统一：state.json、TUI 实时读数、交付物文件三者一致。

### ③ 确认按钮按下后不回列表
**根因**：`_submit_new_taskbook` 成功后**留在表单**（可被重复点「投递」→ 同一份任务书投两遍）；reject 路径本就回列表（实测 `view=taskbooks`、面板 `display=False`）。
**修法**：投递成功 → `_open_taskbooks()` 回列表并在**列表面**报 `[√] 已投递…`；reject 的既有行为一并钉进回归。

### ④ ESC 再进双选残留
**根因**（读 Textual 8.2.8 源码 + 实测）：`_set_radio` 逐个写 `btn.value = (i == index)`；实测**重开面板后** `values == [True, False, True]` —— 残留项与默认项**同时为 True**（双选残留；`-selected` 类只落在一项，但值不一致）。
**修法**：改**两段式**——先全清 False，再把目标置 True。修复后实测 `values == [True, False, False]`（模式回①、优先级回「中」、批语清空）。
