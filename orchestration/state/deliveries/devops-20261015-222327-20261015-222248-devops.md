## 222248：`plan edit` —— 改环节字段不必再猜折行

**根因**：`plan new` 登记时把 YAML 交给 `yaml.safe_dump` **重排折行**，于是照自己写入时的折行写 `old_string` 的 Edit **逐字对不上**（实测连续两次 `0 occurrences found`，每次都要先 `sed` 读回）。

**做法（建议的两支都做了）**：
- **新命令** `pysci-orch plan edit <id> --step S (--brief|--append-brief|--dirs)`：说「改什么」即可——自动写盘 + 按环节 id 对账（**护栏同 amend**：rework 模板必留节点 + 已 started 结构冻结）；不明环节会**列出可用环节**而非裸报错；未给编辑项则拒绝（rc=2）。
- **文档**：command-surface 加该命令行 + 一句「**改环节别手编 YAML**（登记会重排折行，old_string 逐字对不上）」。

**criteria 逐条**：①「改后 `plan amend` 对账绿」→ 有专测；② 核心用例「往既有叶子 brief **追加一句**、操作者**无需先读回原文**」→ 有专测（`--append-brief`，只动点名环节）；③ 进度保持（对账按 id 保状态）也有专测。

## 222249：白名单「声明即注入」入档 + 解析失配可见

**做法**：
- **文档**：`dispatch-playbook.md` 新增「白名单：**声明即注入**」节——任务书白名单段声明的目录**自动注入** `PYSCI_TASK_DIRS`，与派发侧 `--dirs`、plan step `dirs` **取并集**（保序去重）；声明了却解析不出目录时派发口出声。
- **代码**：`dirs_with_taskbook_whitelist` 的告警条件由「**两者皆空**」放宽为「**声明了白名单段但解析不出目录**」——**有显式 dirs 时不再静默丢弃声明面**（提示语区分两种情形）。

**⚠️ 顺带揪出并修掉一处潜伏 bug**：那条告警的守卫 `_WHITELIST_HEAD_RE = re.compile(r"^#{1,6}\s*白名单")` **缺 `re.M`**，`^` 只锚**串首**——真实任务书都以「# 任务书…／背景／目标」开头、白名单段在中间，于是 `search(text)` 恒 False ⇒ **152939-fix3 承诺的「可见失败」实测从不触发**（修静默失败的代码本身静默失效）。实测对照：

```
$ search(tb) 无 re.M -> False      # 白名单段在中间
$ search(tb) 加 re.M -> True
```

已加 `re.M` 并就地注释因果；逐行 `.match(ln)` 的既有用法不受影响。
