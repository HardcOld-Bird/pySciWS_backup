# 任务书：夜航热生效 + 注入文案修订（合并单；用户裁决 2026-10-15 晚，裁决原文要点如下，不得违背）

## 用户裁决（实质面）
1. **实现热生效**：`[night] enabled` 变更在**下一轮输出**即生效，不再要求重启会话。
2. **差分措辞禁令**：关闭差分**不得**写「立即停止自主推进」类字样——本项目**始终鼓励自主推进**
   （twin 即为此设计），夜航只是为该模式加一道强调和硬保险（附带开关）。关闭=收回夜航授权、
   恢复常规交互（可向用户提问/等待），**自主推进照常**。
3. **LLM 永不拨开关**：不实现「LLM 拨回」、不实现「时限到期」——开关只归用户手动拨动。
   用户不显式关，夜航可一直开着（常见态：inspector 巡检持续产生任务，夜航常开无害）。
4. 政策④（终态）相应改写：达成终态写一段收尾总结即结束推进，**不改开关**。

## A. 热生效机制（差分注入）
1. 回合边界（Stop 钩子，或实测可用的每回合读点）比对 `[night] enabled` 与**会话内上次读数**
   （持久标记；注意多会话并存——按 session_id 记 last-seen 或等价机制，防会话间互相误报）；
2. **无变化：零输出、零开销**；
3. 关→开：下一轮输出即注入夜航授权全文（同 SessionStart 注入文本）；
4. 开→关：下一轮输出即注入**刹车差分**，措辞按上述禁令，示例：
   「夜航已由用户关闭：夜航授权书失效，AskUserQuestion 拦截放行，恢复与用户的一问一答；
   自主推进照常（项目常态），无需停摆等用户」；
5. 通道取实测可用者：Stop 钩子 rewake 消息（watch-arm asyncRewake 既有通道）或 harness 支持的
   回合注入；都受限则退化为每回合最小提示行（一行状态）+指引读政策全文（改动须保持
   fail-open，watch 语义零回退）；
6. 既有热行为保持：night-gate（AskUserQuestion 拦截）继续每回合现读，不受本单影响。
