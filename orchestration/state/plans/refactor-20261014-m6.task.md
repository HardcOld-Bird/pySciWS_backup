## 背景

`backpressure.py` 现状是**半接线**：活跃会话注册表写侧（`note_session`/`heartbeat`）
全仓零调用者、注册表实际为空；延期（`defer_until` 指数退避）只在 devops backlog 链
生效（`workflow.backlog_defer`）。本环节把写侧接上、把延期语义推广到全部队列，
完成 §3.3 硬验收。

## 目标（三件，缺一不验收）

1. **写侧接线**：所有做 LLM 派发的 worker（m4 成员队列 worker、devops drain、
   benchd——inspector 自循环视情况）：
   - 拉起即 `note_session` 登记（`state/active-sessions.json`）；
   - 运行中**周期 heartbeat**——周期须显著小于判死阈值（现阈值 >10min 无心跳判死，
     建议 heartbeat ≤3min）；**长 job（>10min）不得被误判死**，用后台心跳线程/等价机制
     保证 job 进行中也有心跳；
   - 完成/退出即注销；判死回收沿现阈值语义，与 workq 孤儿回收协同（不重复回收）。
2. **全队列 defer 语义**：
   - 出队单点（m4 预留）先查 backpressure 延期纯函数（指数退避 2→4→8min、次数闸 6、
     壁钟闸 1800s——沿现模块，不重写）；`defer_until` 未到期不被取；
   - bandwidth 类失败回队挂 `defer_until`（沿 `workflow.backlog_defer` 语义推广到
     成员队列；devops 既有语义不动；bencher 队列如适用则同等对待）；
   - 到期自动重取，次数/壁钟闸触顶的处置沿现 devops 语义（停止并上报）。
3. **观察面**：`pysci` TUI「队列与运行」模块显示延期读数（沿现 `_line_defer` 数据源/
   措辞，m2 模块已归并）；`orch status` 队列段同步可读；事件层可发延期相关事件
   （如 QUOTA-STOP 沿现制）。

## 验收预期（机械——§3.3 硬验收原文）

- **有 worker 活跃时 `active-sessions.json` 非空**（mock 派发集成测试），完成后清零；
- **构造 bandwidth 失败可见条目挂 `defer_until`、到期重取**，次数闸/壁钟闸生效；
  成员队列与 devops backlog 两条链都验证；
- `pysci`「队列与运行」模块可见延期读数（Pilot 测试或纯函数断言）；
- 长 job（>判死阈值）不被误判死（测试用假时钟/短阈值验证心跳续命）；
- `uv run --no-sync pytest` 全绿（1316+ 基线），全仓无回归。
