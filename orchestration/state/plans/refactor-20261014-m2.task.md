## 背景

m1 已定案 Textual 并立起裸 `pysci` 入口与 TUI 骨架。本环节把骨架长成**主菜单交互模型**
并完成旧概览项的模块归并——这是交互式控制台的主体框架。任务书/计划等模块的详情功能面
留后续环节（m3/m5），本环节只做结构与只读详情。

## 目标（四件，缺一不验收）

1. **主菜单交互模型**（REFACTOR.md §2.2）：
   - 每模块一行：标题（左）＋ 更新徽标（右），**不显示简介**；
   - ↑↓ 切换选中；选中项高亮（加粗 + 彩色 + 装饰元素，样式自定但要有「精美」追求）；
   - 选中项下方**展开 3–5 行概览板**（复用 `mirror.py` 纯读数函数裁剪，§2.5 不重写读数）；
   - Enter → **全屏详情视图**（仅展示该模块）；Esc/← 返回主菜单；
   - 进入详情视图即写该模块水位（见 2）。
2. **更新徽标与水位**：真源 `orchestration/state/mirror-seen.json`（`{module: cursor}`）。
   每模块实现 `updates_since(cursor)`：有记录流的数据源（决策/回退/队列等）按记录数/时间
   计数；无记录流的状态读数可用指纹（上次详情读数指纹变化即「有更新」）。徽标形如
   `● NEW` / 数字 / 灰点。要求**可解释**：徽标数字与详情内容对得上；文件损坏 fail-open。
3. **模块归并 12→7**（REFACTOR.md §2.4 表）：任务书 / 计划与派发 / 队列与运行 /
   盲审与审查 / 系统与路由 / 决策审计 / 待决与验收。
   - 「任务书」「计划与派发」详情放**占位**（m3/m5 充实，如实标注「占位」）；
   - 现 `mirror.cmd_decisions` 全貌迁入「决策审计」详情视图（数据层复用，不复制代码）；
   - `journal` 编号分流菜单迁移进 TUI 口述动作（主菜单快捷键 `j` + 「待决与验收」内入口，
     偏好/指令二分法理不变）；
   - 宪章读数归「盲审与审查」（组长钉死，不再择一）；
   - **注册纪律不变**：新增「需用户关注事项类型」必须进模块读数登记（§2.4）。
4. **通道不回归**：非 tty `pysci` 仍输出静态 status（逐字等价 `mirror.cmd_status`）；
   `pysci status|journal|decisions` 子命令行为不动（m7 才转 LLM 通道）。

- 全仓测试无回归（含 m1 的 6 项与 README 一致性测试）。

## 纪律（违约即返工）

- 数据层单一实现：读数函数留在 `mirror.py` 纯函数层，TUI 只调用不复制（§2.5）；
- 本环节不动 pyproject.toml；若确需改，改后必须 `pysci-dev venv-sync`；
- 编辑项目文件用文件编辑工具；CLI 首选裸 `pysci-X`；
- 交互细节遇蓝图未定处按 §2.2 宗旨自定，但**不得引入新的命令式入口**；
- 交付按 pod 交付协议 XML（`<result>`/`<blocked>`）；blocked 带 tags 与 reason；
  改进建议带合法 `kind` 属性。
