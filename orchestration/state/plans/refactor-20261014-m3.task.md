# REFACTOR 施工 M3：任务书模块 + data/taskbooks/ + TASKBOOK-NEW 唤醒

（计划 refactor-20261014 环节 m3；蓝图=仓库根 `REFACTOR.md` §3.4 + §2.4 #1。
交接物：m2 的 `tools/tui/modules.py` 七模块注册表（「任务书」现为占位）、
`tools/tui/watermark.py`、`mirror.py` 纯函数层。）

## 背景

任务书是用户向组长投递**大任务**的载体（用户裁决 ① 落点 `data/taskbooks/`，入 git、
用户可见可编辑）。本环节建存储与状态机、TUI 投递/批复界面、组长程序化查看面，
以及落盘即唤醒组长（TASKBOOK-NEW）的最小接线。

## 目标（四件，缺一不验收）

1. **存储与状态机**（§3.4）：
   - `data/taskbooks/<id>.taskbook.md`（元数据头：ts / title / status / source=
     mirror-tui|llm ＋ 用户纯文本正文）＋ `<id>.state.json`（状态机 + plan_id 链接 +
     用户批语字段）；id 形如 `tb-YYYYMMDD-HHMMSS-<slug>`；
   - 状态机：`new → planning → active → delivered → accepted | rejected`；
     rejected **带用户批语回 new**（返工重拆解，批语持久保留于 state.json）；
   - 写入 data/ 前过 `pysci.paths.assert_within_data`；本目录**入 git**（用户裁决 ①，
     切勿加进 .gitignore）。
2. **TUI「任务书」模块**（m2 的占位充实为正身，§2.4 #1）：
   - 列表三段：现有大任务（new/planning/active）、已完成待批复（delivered）、
     历史（accepted/rejected 带批语）；
   - **新增**：多行纯文本编辑器（Textual TextArea），提交时程序化组装时间等元数据并落盘；
   - **批复**：accept / reject＋批语（交互输入，写回 state.json，rejected 回 new）；
   - 更新徽标接进 m2 水位体系（待批复 delivered 或新任务书即「值得关注的更新」）。
3. **组长程序化面**：`pysci-orch taskbooks list|show <id>`（只读），加**最小状态推进**
   （如 `taskbooks link <id> --plan <pid>` 记 plan_id 并置 planning；被链计划完成时
   置 delivered——可经 `taskbooks sync` 或等价机制幂等对账）。子命令设计可自定，但须
   覆盖：查看、链接 plan、完成联动 delivered；**用户 accept/reject 只经 TUI**。
4. **TASKBOOK-NEW 唤醒**：新任务书落盘即产生唤醒组长的事件。当前 watch 只认 5 类事件
   ——**最小扩展** `watch.py` 识别 TASKBOOK-NEW（扫 `data/taskbooks/` 增量，基线记
   `state/watch.json`），命中即走现有唤醒链。m5 会把它并入统一事件层：本次实现保持
   接口面窄（事件名、检测函数、基线字段），并在代码注释注明「m5 收编」。

## 纪律（违约即返工）

- 状态机真源 = `<id>.state.json`，任何界面（TUI/CLI）不得各存一份状态；
- 数据层单一实现：读数进 mirror/taskbooks 纯函数层，TUI 只调用；
- 本环节不动 pyproject.toml；确需改则改后必须 `pysci-dev venv-sync`；
- 编辑项目文件用文件编辑工具；CLI 首选裸 `pysci-X`；
- 交付按 pod 交付协议 XML（`<result>`/`<blocked>`）；blocked 带 tags 与 reason；
  改进建议带合法 `kind` 属性。
