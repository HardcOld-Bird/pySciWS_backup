## 背景

普通派发今天是进程级阻塞（`do_dispatch` → `run_headless` Popen+communicate 等完）。
本环节为 **7 专职（sim/writing/figure/theory/lit/drawing/model3d）+ deputy + reviewer**
建立 FIFO 队列与 worker 生命周期，为 m5 的事件驱动 plan advance 提供承托。devops/bencher
既有队列与语义**不动**（组包保留给 devops；生产组员一律不组包）。

## 目标（四件，缺一不验收）

1. **成员队列**：每成员一队 `orchestration/state/queues/<member>.json`，基于 `workq.py`
   原语（状态机 `pending→in_progress→done|failed`、take_next、孤儿回收、keep 20）。
   条目字段最少含：id、member、task/task_file、dirs、model/effort、plan/step 联动位
   （m5 用）、review 附属位（见 3）、session 复用策略、created、结果摘要位。
   **入队 API + orch 命令面**（如 `orch queues enqueue|list`，命名自定）。
2. **worker 生命周期**（推广 devops drain 模式，非常驻）：
   - 入队且无存活 worker → `wake_<member>` 拉起分离进程（per-member 锁防重入）；
   - worker FIFO 消化：出队→复用 `do_dispatch` 执行（会话策略沿派发惯例：默认 latest，
     可 new）→ 记结果 → 下一条；**队空写 .done 摘要退出销毁**；
   - 孤儿回收：worker 死亡遗留的 in_progress 由 workq 既有 reset_orphans 语义恢复；
   - 出队点**保持单点**（m6 在此接 backpressure 延期检查，本环节留好接口即可，不预实现）。
3. **reviewer 附属语义**：job 条目支持 `review` 附属位（reviewer 环节任务）；宿主 job
   交付后**自动向 reviewer 队列投附属子 job**（父子 id 关联），reviewer 交付回填宿主
   记录；宿主 job 的「完成」在宿主+其 review 都收尾后才成立（= 未来一个通知单元，
   事件发射是 m5 的事，本环节把结构与顺序做对）。review 不需要的 job 完成语义不变。
4. **组包边界**：生产组员 job 相互独立、**一律不组包**（batch_size=1 语义）；
   devops backlog 的组包、延期、needs_leader 语义**原样保留**（既有测试不许回归）。

## 验收预期（机械）

- `uv run --no-sync pytest` 全绿。新增至少覆盖：入队→worker 消化→done 结果落盘；
  队空退出销毁；per-member 锁防双 worker；孤儿回收；reviewer 附属 job 父子联动与
  「宿主+review 才算完成」；生产队列无组包（同队多条逐条派发）。
- do_dispatch 层零破坏：既有 devops/bencher/inspector/plan 流程测试全过；
- `orch` 命令面能入队/查队，`orch status` 队列段能读出新队列水位（观察面接入）；
- 真实 LLM 派发不在本环节验收范围（测试用 mock do_dispatch），但接口与
  `run_headless` 对齐。
