**（E6-prep，REFACTOR v1.0 §8/§9）twin pod 脚手架 + PREFERENCE.md v1 草案（readonly_extra 只读、冷启动纪律；代理裁决不启用）**

kind: usability
背景与授权：REFACTOR v1.0 定稿 + 委托 §15。**边界**：本单只建机械面与草案；
PREFERENCE.md **生效确认**与 twin **上线宣告**留用户（§9.4 例外条款），故本单
不接通任何代理裁决/终裁回退的启用开关（E3/E6 回退链代码就位但默认休眠）。

规格：
1. pod `orchestration/pods/twin/`：按六 pod 脚手架先例批量建（charter 含：
   无记忆纪律=每次冷启动永不 resume、轻量笔记原则特化=AGENTS.md 固定最小
   占位不积累、判断输出格式=选择+理由+置信度 JSON、readonly_extra 保护
   PREFERENCE.md 与 charter）；
2. `pods/twin/PREFERENCE.md` **v1 草案**：从 README §13 全部用户裁决 +
   preference-journal（含本轮委托记录）蒸馏宪章级偏好条款（如：硬代码优先于
   软条款、不建重叠实现、决策记录写在决策发生处、宁可粗糙但在用、二选一
   决策形式、先决策后问责+全量留痕、成本敏感=免费/最低档优先、8KB 预算
   纪律、自覆盖但精确豁免自指）——标注「草案 v1，待用户确认生效」；
   manifest 追加 twin 部署目标 + `orch skills sync`；
3. registry 注册 twin：model=flash、max_turns 小（单跳判断）、readonly_extra
   ["PREFERENCE.md"]、extra_dirs=项目根（只读）；guards 接线（pod-guard/
   delivery-gate）与十 pod 先例一致；
4. `orch taste <case>` 命令：冷启动派发（强制 `--session-id` 新 uuid，实现
   层面禁 resume——代码硬保证无记忆）、注入 PREFERENCE.md + 案卷、解析
   结构化输出落 `state/evals/taste/<case>.json`；**开关**：
   registry.taste_enabled 默认 false（用户确认草案后置 true 才对外服务；
   未启用时 orch taste 打印「twin 宪章未生效」并拒绝派发）；
5. `pysci-mirror` 骨架（console script，devops 维护）：`status`（全景占位：
   待盲审/宪章状态/taste_enabled/队列水位）与 `journal`（机械分流：
   菜单选①偏好陈述→journal 追加；②行动指令→state/mirror-queue.jsonl，
   组长 orch status 可见）——review/distill/overrides 留 E6 后续单；
6. 阳性测试：twin 冷启动强制（传 resume 被拒）、readonly_extra 拦截 PREFERENCE.md
   写、taste_enabled=false 拒绝派发、mirror journal 分流落点对。

success_criteria：
- doctor 十一 pod 全绿；twin pod 冒烟一跳（--text 自检）经 taste 通道被拒

  实锤；
- `pysci-mirror status` 输出全景项、`pysci-mirror journal` 分流正确；
- PREFERENCE.md v1 草案落盘并标注待确认；全量套件无回归。
