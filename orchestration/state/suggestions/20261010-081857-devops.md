# 改进建议（devops，待审批）

**缺陷类（附证据）：auto-wake drain 的运行态文件未纳入 .gitignore，污染 git status 且有误提交陈旧锁的风险。**

证据：本任务全程 main 的 `git status --short` 持续显示两项未跟踪运行态文件——
```
?? orchestration/state/devops-runs/
?? orchestration/state/devops.lock
```
二者是我上一任务（20261010-orch-auto-wake-devops）引入的 drain 运行态产物：`devops.lock` 是短暂的互斥锁（含 pid/started），`devops-runs/*.log|.done` 是每次 drain 的审计日志。它们既非被 gitignore、也未入库，故每次 `git status` 都出现，容易被 `git add -A` 误纳入提交——一旦把带死 pid 的陈旧 `devops.lock` 提交入库，语义上是错的（尽管 `_lock_live` 的死 pid/超龄 stale 接管能兜底，不至卡死）。

建议（择一，由组长裁定）：把 `orchestration/state/devops.lock` 与 `orchestration/state/devops-runs/` 加入相应 `.gitignore`（lock 属纯运行态，强烈建议忽略；run 日志若要留审计痕迹可另行裁决保留或忽略）。属我自有基础设施的小卫生修复，但为守「一笔提交一个主题」未夹带进本次绘图修复，故走提议通道。优先级低。
