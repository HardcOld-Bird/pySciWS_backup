success_criteria: 用 5.0-pro（不支持 png 输出）出图后，jpeg→`adjust --out x.png` 得到的 png 应自动带上与 `gen` png 输出同款的 `pysci:prompt`/`pysci:model`/`pysci:backend` 内嵌溯源；或 `adjust` 提供 `--provenance/--from-ledger <runs/x.json>` 开关一键注入。

场景：本 pod charter 要求「生成图必须入库 LEDGER，走生成台账 / **PNG 内嵌溯源**」。但实测 `imagine models` 显示本账号可用的 5.0-pro/flash 均**不支持 `output_format=png`**（仅已下架的 `doubao-seedream-5-0-260128` 支持），故「jpeg 出图 → `adjust` 转 png」是唯一路径；而 `gen` 的 jpeg 本身不带 `pysci:*`、`adjust` 也不写入。

易错点：任务书一律要求 `.png` 交付 → 交付图**静默缺失内嵌溯源**（页4 的成品有 pysci:*，本页经同样 jpeg→adjust 路径却没有），仅靠 `runs/*.json` 台账兜底；且 `runs/*.json` 的 `b64_json` 落盘时已被剥离（`AGENTS.md` 踩坑 4），台账无法回放图像，一旦漏归档即不可追溯。

期望形态：`adjust` 在 `--out *.png` 时自动从同名 `runs/<slug>.json` 继承 provenance 写入 PNG 文本块；或在交付流程里提供一个「补写 png 溯源」的官方子命令，避免每个绘图组员各自手写 `PngInfo` 脚本（本次即是如此绕过）。
