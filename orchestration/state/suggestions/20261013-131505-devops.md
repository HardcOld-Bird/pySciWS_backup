**`pysci-dev worktree add` 不播种 sessions-runtime，fresh worktree 合并必撞「会话数 0 < baseline」闸且报错指引误导**
场景：从**最新 main（229a238）**执行 `pysci-dev worktree add 20261013-124017-salvage`，worktree 的 `orchestration/state/sessions-runtime.json` 是空壳（1 member / 0 sessions）；`pysci-dev worktree merge 20261013-124017-salvage` 以「worktree 侧会话数 0 < main baseline 45——cp 会覆盖更丰富的 main 运行态、丢会话，中止；核对 worktree 是否 stale（应从最新 main 起 worktree add）」拒绝合并。本例正是从最新 main 起的，文案指向的成因不成立；真因是 add 只落空壳、不从 main 播种运行态，导致每个新 worktree 的首次合并都要人工 `cp sessions-runtime.json` 才能过闸（本单实测：cp 后重跑一次通过，45→45）。
success_criteria：`pysci-dev worktree add <id>` 之后 `orchestration/state/sessions-runtime.json` 与 main 等富（或 merge 侧识别「add 空壳」形态直接跳过 cp 并沿用 main 运行态），fresh worktree 一次 `worktree merge` 全程零人工 cp；若闸仍触发，报错文案只列与成因一致的处置项。
