**`dispatch.do_dispatch` 归档 reply 的 `shutil.move` 对「源文件已缺失」不幂等 → worker 异常退出；批次**已派发、未结账**即坠落 → 该条目被重派而未先证伪「上一跳已起活会话」→ **同一隔离面出现两个并发活跃写者**（本单即为被重派出来的第二个写者，白烧一跳且与在途写者抢面）。**

复现命令与实际输出：
```
$ ls orchestration/state/replies/devops/20261015-085823-devops.md
ls: cannot access '…/20261015-085823-devops.md': No such file or directory
$ git status --short -- orchestration/state/replies
 D orchestration/state/replies/devops/20261015-085823-devops.md

  File "…/dispatch.py", line 1596, in do_dispatch
    shutil.move(str(p), str(sent / p.name))

orchestration/state/queues-runs/devops/20261015-122406.log     # ← 只有 .log，无 .done（该 job 未结账）
```

影响链（三跳）：reply 源被先移走 → 归档不幂等 → worker 崩 → 批次未结账 → 重派 → 双写者（12:53:15 已起会话 e7fd0526/pid6304，13:09:19 又派给 478b69ac；并发窗口 16 分钟，且两者写同一 worktree）。
注：**sid 在途闸本身是好的**（日志见 `probe_sid_inflight sid=478b69ac` → `session_selected sid=e7fd0526 resume=False reason=prev_alive`）；缺的是**重派前对「该条目上一跳已派发且会话仍活」的证伪**，以及对归档 move 的幂等守。

success_criteria:
- `do_dispatch` 的 reply 归档对**源缺失 / 目标已存在**幂等：move 失败按「已归档」处理（落一行 `reply_already_moved` 或等价埋点），**不得**让 worker 异常退出。
- 阳性用例：预置 `sent/<id>.md` 已存在而源文件缺失，驱动一次 dispatch 收尾 → 断言 rc 正常、`.done` 落盘、日志无「批次派发异常」。
- 批次「已派发、未结账」的条目重派前须先证伪在途：同任务同名隔离面已有活写者（或同名 worktree 仍注册且分支未合）→ **不重派**（或换面 `<面>-r<N>` 重建），杜绝同一面双写者。
