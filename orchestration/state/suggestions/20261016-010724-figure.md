**缺陷**：reviewer bench 的 `rev_cover.py` 用**缓存**的 `white_field.png`/`white_radar.png`（「文字置白版」）构造墨迹蒙版，改图后若未先重生成缓存，蒙版会**跨版本污染**并给出假 FAIL。该脚本本身不负责重生成（只有 `rev_diffink2.py` 顺带覆盖这两个文件），两脚本无依赖声明。

**复现**（本 pod 内，只读调用 reviewer 脚本，输出件落本 pod bench）：
```
# 1) 用旧版白字件（在改 Sim. 定位前的脚本上跑 rev_diffink2 生成）复测**新版**图：
$ uv run --no-sync python orchestration/pods/figure/bench/rev_cover.py
     77: 覆盖黑线像素 = 0
  === 场图：文字墨迹 到 真实弧 的最小距离（6 面板）===
     77: min=1.0px = 0.04mm        ← 假 FAIL（该 1.0px 来自旧标签位置，已被移走）
# 2) 先跑 rev_diffink2.py（重生成白字件）再复测：
$ uv run --no-sync python orchestration/pods/figure/bench/rev_cover.py
     77: 覆盖黑线像素 = 0
     77: min=49.2px = 2.08mm       ← 真实值
```
期望输出：任一次复跑都得到与图同版本的判据值。

**动作**：建议 `rev_cover.py` 在读取白字件前先校验其新鲜度（如对比缓存件与受审 PNG 的 mtime/尺寸，或把「重生成白字件」内置为前置步骤并在输出里注明所用白字件的生成时间）；至少在脚本抬头写明「必须先跑 `rev_diffink2.py`」，避免复审按原样单跑时被假 FAIL 拦截。
