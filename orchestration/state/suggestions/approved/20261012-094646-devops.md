kind: defect
**pysci-dev 的跨树自检误拦「标准 worktree 配方」，且 mdgen-check 的相对路径按 cwd 解析——同一配方下它校验的是另一棵树的字节**

上游条款：跨树自检是我上批交付的（commit 73a2090，backlog 20261012-010508-devops），worktree 测试配方是 README §7/本技能规定的（`PYTHONPATH=<wt>/src uv run --no-sync`，**前提 cwd 在 worktree 之外**）。两者在真实作业里互相矛盾，本轮合并前首次跑 sync 即撞墙。

复现 1（误拦，rc=2 拒执行）：
```
$ cd D:/XXXIIIGGG/projects/pySci/pySciWS          # 主树根（配方要求待在外面）
$ PYTHONPATH=".qoder/worktrees/20261012-023430-devops/src" pysci-dev sync
[!] 跨树执行：脚下是另一棵树，而本进程的代码面/项目根指向别处——
    cwd 所属项目根 = …\pySciWS
    PROJECT_ROOT  = …\pySciWS\.qoder\worktrees\20261012-023430-devops
    worktree 内请带代码面覆盖：PYTHONPATH="<wt>/src" pysci-dev …，或加 --force
    已拒绝执行（rc=2）
```
期望：放行。此处 PROJECT_ROOT 正是我**要**操作的那棵树，脚下是它的主仓——与护栏要防的事故形状相反（事故=脚下在 worktree、代码面指 main）。护栏给的解法（带 PYTHONPATH）恰是触发条件本身。

复现 2（校验错树，静默假基准）：
```
$ 同上配方 + --force，参数写相对路径
$ pysci-dev mdgen-check orchestration/skills/devops/SKILL.md
  [OK] orchestration\skills\devops\SKILL.md  8178B→8178B  post_sha256=926a418b1f843ec9
$ 而 worktree 内该文件实际 8142B（8178B 是 main 侧未含本批改动的旧真本）
```
期望：`mdgen.py` 收到的 `Path(p)` 是相对的、按 cwd 解析，而其余路径口径全是 PROJECT_ROOT——跨树时它读写的正是「另一棵树」。mdgen-check 的立身之本是「内容等价性以钩子终态 post_sha256 为基准」，跨树配方下这个基准取自过期的别的树字节，「验证已过期」窗口被重新引入（本单靠 --force 才看见，改写 0 个纯属侥幸）。

建议修法（两处，均小）：① 判据从「own ≠ PROJECT_ROOT」收窄为「own ≠ PROJECT_ROOT **且** own 不在 PROJECT_ROOT 之上包住它」：当 `PROJECT_ROOT` 位于脚下树之内、且 `PROJECT_ROOT/.git` 是**文件**（linked worktree 的特征，无需起子进程）→ 判为标准配方放行；脚下在 worktree 而代码面指外层 main、以及两树无隶属关系（真·跑错项目）仍照旧拦。② `cmd_mdgen_check`/`mdgen.main` 里相对入参一律 `PROJECT_ROOT / p` 解析（或跨树时直接拒绝并要求绝对路径）。

success_criteria：
- 两条 repro 各一条阳性单测：(a) cwd=主根 + `PYTHONPATH=<wt>/src` 下 `pysci-dev sync`/`doctor`/`mdgen-check` 放行且读写对象全在 worktree（台账与副本落 `<wt>/orchestration/…`）；(b) 反向事故形状（cwd 在 worktree、代码面指 main）仍被拦、rc=2。
- `mdgen-check <相对路径>` 在跨树配方下打印的字节数与 post_sha256 取自 `PROJECT_ROOT` 下同名文件（单测：两棵树各放一份内容不同的同名 md，断言取到 worktree 那份）。
- 本轮已用 `--force` 绕过（复现 2 靠改传绝对路径才得到正确基准 8142B/post_sha256=33e67a1df555b35e），修好后标准配方不再需要 `--force`。
- 全量套件无回归（当前基线 2192 passed / 37 skipped）。
