# tier-a 立案去重只护 pending 面：已批在途/已销案会重复立案（双记账）

kind: defect
source: leader
fingerprint: tier-a-dedup-gap-20261017

## 现象（实证，2026-10-17 清账时实测）

`tier_a_sweep`（workflow.py:1728-1737）两道去重：①同指纹 24h 窗；②`_open_tier_a_keys`
仅扫 **pending** 提案。缺口三处：①案 approve 进 backlog 后实施在途（可能数日），次日
新撞**换指纹桶**（fp=tag|member|最新行日期）+ open_keys 已不含它 → 每日重立，backlog
被同题案灌满；②案被 reject/销账后同理（实证：024522 刚销账、同指纹 051318 立即重立，
因 24h 窗也已过）；③指纹含日期使「同一未修好的问题」跨日即视为新指纹，24h 窗形同虚设。
旧注释自陈「缺这一道，窗口桶每天前进就会每天再立一次」——但那道保护只在 pending 期间
有效，approve/reject 后即失守。

success_criteria:
- 去重键扩展为「(tag, member) 级」：该键存在**未销账**关联（backlog 条目 pending/
  in_progress、或 approved 提案未 done、或 reject 理由含「已落地/已承接销账」且承接单
  未 done）即不重立；指纹日期仅作参考不作去重键；
- 回归测试：构造「已 approve 在途 + 窗口每日新增撞」连续 3 天，断言只立案 1 次；
  构造「已 reject 销账 + 承接单在途」断言不重立；承接单 done 后新撞方可再立；
- `uv run --no-sync pytest tests` 全绿。
