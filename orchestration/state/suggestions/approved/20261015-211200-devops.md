# 改进建议（devops，待审批）

kind: usability
delivery: leader-reflection
来源：组长工作摩擦反思（2026-10-15 第二轮补充）

**场景**：`plan adhoc` 的阻塞语义未文档化——它是**同步执行到完成**（本次 105s 全程阻塞），
与 `plan advance` 的「入队即返回」相反；组长按后者的直觉放前台跑，撞 Bash 工具超时才被
自动转后台。

**证据（复现 → 实际 → 期望）**：
- 复现：`pysci-orch plan adhoc drawing --dirs ... --text "..."`（补派单，成员 1 跳
  105s）。command-surface 对 adhoc 仅一行「计划外单件事」，无阻塞语义；SKILL「长任务
  必须后台运行」列出的是 `plan run/dispatch/review`，未点名 adhoc。
- 实际：命令前台阻塞 120s 撞工具超时，由 harness 降级转后台后才拿到结果（多一轮查询）。
- 期望：命令面注明「adhoc 同步阻塞至计划完成，长任务须 run_in_background」。

**建议**：command-surface 的 `plan adhoc` 行补一句阻塞语义 + 后台纪律；SKILL「铁律 3」
的命令枚举把 `plan adhoc` 纳入「须后台」名单。

success_criteria:
- command-surface 或 SKILL 有一处明示 `plan adhoc` 同步阻塞及后台用法；
- 与 `plan advance` 入队即返回的差异在同一处对照注明。
