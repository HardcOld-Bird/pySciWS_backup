# 改进建议（leader，待审批）

**（E3-live，REFACTOR v1.0 §4 渠道修订）仲裁团三席官方直调（deepseek/glm/kimi）+ SiliconFlow 回退告警面 + minimum 火山方舟渠道验证**

kind: usability
success_criteria: 见文末。背景：用户 2026-10-12 渠道裁决（REFACTOR §4 修订条
已落，journal kind=ruling 留痕）：三席官方直调减平票、SiliconFlow 降回退且
回退必须告警、minimum 选型 doubao-seed-2.0-mini（火山方舟）。

规格：
1. `registry.jury` 改**逐席 provider 结构**：`{name, base_url, model,
   key_env}` 三席（DEEPSEEK_API_KEY→api.deepseek.com/v1；GLM_API_KEY→
   bigmodel 兼容端点；KIMI_API_KEY→moonshot 端点，具体 base_url 以各官方
   文档核）；panel 型号清单**排除 Qwen 系**的硬校验保留。
2. Key 读取三级回退：进程 env → **HKCU\Environment 注册表直读**（会话未重启
   也能就位）→ 缺失即该席标 unavailable；任何日志/留痕不得含 Key（哨兵既有）。
3. 回退面：`registry.jury.fallback`（SiliconFlow，独立开关）仅当 ≥1 主席
   不可达时启用；**启用即在案卷、status 判决包健康段、mirror 三处显式告警**
   「回退席已激活——请用户处理主席」（REFACTOR §14 单点条款的告警化）。
4. 双序/多数/escalate 逻辑不变（E3-prep 已交付），逐席 provider 化仅是
   传输层改造。
5. **minimum 火山方舟验证（调查项，可 blocked 上报）**：压测必须经 Qoder
   headless 驱动 → 验证 Agent Plan 专用 Key 能否注册为 Qoder BYOK 模型
   （查 `--list-models` 与 BYOK 配置面；VOLC_AGENT_PLAN_KEY 读法同②）；
   可行→minimum 重映射 doubao-seed-2.0-mini（护栏级，结果呈用户后落）；
   不可行→维持 flash 并写替代结论（等用户提供通用 API Key 再议）。

success_criteria：
- 三席 smoke：一真实争议案 → 三票+双序一致+多数裁决+逐席 usage 落盘；单席
  Key 缺失场景该席标 unavailable 而非全案崩；
- 人为断开一主席 → 回退告警在案卷/status/mirror 三面可见（阳性用例）；
- minimum 调查有书面结论（可行则含一次 doubao 压测实测行；不可行则替代说明）；
- 全量无回归。

**补充（组长 12 日 16:5x，用户澄清后）**：Key 载体=**项目根 `.env`**（用户口述
确认，6 变量齐、gitignored 实锤、python-dotenv 可用）——规格第 2 条 Key 读取
回退链修正为：**进程 env → 项目根 .env（python-dotenv 加载，勿打印值）→ 缺失
标 unavailable**。bencher 副本已自动复制 .env（见 164434 运行日志），E3-live 与
之对齐即可。无需用户重启终端。doctor 既有哨兵继续保证 .env 不入库。
