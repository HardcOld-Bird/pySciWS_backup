## 调查结论（E3-live 实施回填，devops，2026-10-12T19:5x+08:00）

**第 5 条 minimum 火山方舟验证 = 不可行 → 维持 flash，不做重映射。** 三道独立
硬阻塞，任一即足以否决，且**非「等用户提供通用 API Key」可解**：

1. **Agent Plan Key 不是推理凭证**。`VOLC_AGENT_PLAN_KEY` 打 ARK 推理端点
   （`https://ark.cn-beijing.volces.com/api/v3/chat/completions`）实测
   `http=401 AuthenticationError`；它只服务 Agent Plan 的应用面，不能当模型 Key 用。
2. **临时条款下的通用 Key 能认证，但模型没开**。按 17:3x 临时条款读
   `VOLC_AGENT_PLAN_KEY_2` 试用：认证通过、`GET /models` 列到
   `doubao-seed-2-0-mini-260428` 与 `-260215`；但前者
   `http=404 ModelNotOpen`（"Your account 2132903977 has not activated the model
   doubao-seed-2-0-mini-260428. Please activate the model service in the Ark
   Console."），后者 `InvalidEndpointOrModel.NotFound`。→ **裁决名 `doubao-seed-2.0-mini`
   本身也不是合法 model id**（方舟 id 带日期后缀），需要用户先在控制台开通并给定确切 id。
3. **Qoder CLI 的 BYOK 无法脚本化注册**，因此压测路径（headless `-p` 驱动）挂不上
   该模型：`--list-models` 的目录里没有 doubao；自定义模型盘存
   `~/.qoder-cn/.models/<uid>/customs` 是**加密**的，没有可写明文面；
   `qoderclicn config set` 只接受 `vpc_endpoint`（实测 `config get customProvider`
   → "Unknown configuration key: customProvider / Supported keys: vpc_endpoint"，
   在隔离 `--config-dir` 内复核，`config set customProvider.ark.baseUrl …` 同样被拒）；
   `settings.json` 的 `model.name` / `model.preferences.<modelID>` 只在**已就位**的
   模型上做偏好，不能凭空注册。唯一路径是**一次性人工 TUI 操作**
   （`/model` → Custom → Add custom model），无法进任何自动化压测闭环。

**替代结论（供用户裁决）**：minimum 维持现有 flash 档位映射不变；若仍要推进
doubao，需要用户提供两样东西——① 在 Ark 控制台开通具体模型（给出带日期后缀的
model id），② 手工在 Qoder TUI 里完成一次 BYOK 注册。二者齐备后压测可复现，
届时再走护栏级重映射。程序面**未**为 `_2` 变量留任何回退分支（17:2x 条的禁令
在代码层成立：`registry`/`jury`/`bench` 侧只读既有变量名）。
