# 改进建议（devops，待审批）

kind: usability
delivery: leader-reflection
来源：组长工作摩擦反思（2026-10-15 第三轮）

**场景**：编辑已登记 plan 的 YAML（`plan amend` 流程）时，工具会重排折行，人工 Edit 的
old_string 必须逐字匹配折行后文本——本轮连续 2 次 Edit 失败后才改为「先 grep/sed 读回
实际文本再编辑」。

**证据（复现 → 实际 → 期望）**：
- 复现：`plan new` 登记后（YAML 被工具重新折行）修改 f1 环节 brief——用自己写入时的
  折行文本做 old_string。
- 实际：2 次 `Edit` 报 `0 occurrences found`（f1 brief 追加色标裁决、追加色系克制各一次），
  每次需先 `sed -n '/- id: f1/,/effort/p'` 读回实际折行再改，多耗 1 轮/次；且首次登记
  的 YAML 缩进手误还触发过裸 traceback（见 20261015-202556 单，已采纳）。
- 期望：编辑 plan 不必猜折行——amend 指引明示「先读回再编辑」，或提供结构化编辑入口。

**建议**（择一或并行）：
1. `plan amend` 的 [NEXT] 输出加一行「编辑前先读回该段实际文本（登记时会重排折行）」；
2. 或新增 `pysci-orch plan edit <id> --step <sid> --brief/--dirs ...` 结构化小命令
   （内部改 YAML 并自动对账，人不再手编折行）。

success_criteria:
- 文档/[NEXT] 明示折行重排事实与安全编辑步骤；或 `plan edit` 对 brief/dirs 的增改可用
  且改后 `plan amend` 对账绿；
- 以「往既有叶子 brief 追加一句」为用例，操作者无需先读回原文即可完成（或失败时给出
  指向安全步骤的提示而非裸报错）。
