# 改进建议（devops，待审批）

kind: defect
delivery: leader-reflection
来源：组长工作摩擦反思（2026-10-16 第五轮，返工审查链实战）

**场景**：零遮挡类像素判据工具三问题——①`rev_cover.py` 的墨迹蒙版依赖缓存件
`white_field.png`，**图更新后旧缓存导致假 FAIL**（实测把墨迹↔弧线 1.0px 拉回假读数），
现靠任务书人肉提醒「先跑 rev_diffink2 重生成」；②同一判据**两份实现**：figure 的
`bench/check_ink_field.py` 与 reviewer 的 `bench/rev_inkfield.py`（另有跨 pod 拷贝的
`rev_cbargap.py` 在 figure/bench/），违反「同一能力绝不保留两份实现」；③「删文字版
取框线真身」的判法方法学（置白版/差分版各有假阴性）只活在交付文本里。

**证据（复现 → 实际 → 期望）**：
- 复现：b2r 交付实测「用旧缓存复测会把墨迹↔弧线 min 拉回 1.0px（假 FAIL）」；b3r2
  任务书被迫写入复测顺序；b2r 交付「rev_diffink2.py 未含该项打印，以
  bench/check_ink_field.py 补测」——与 reviewer 后来自建 rev_inkfield.py 同判据双实现。
- 实际：假 FAIL 靠人肉纪律防、判据工具分叉、方法学无沉淀。
- 期望：判据工具自防护+单实现+方法学入工具注释/词表。

**建议**：
1. **缓存自防护**：bench 脚本入口比对缓存 mtime 与受审图 mtime，过期自动重生成或
   显式报错退出（杜绝假 FAIL/假 PASS）；
2. **单实现**：墨迹∩彩色/框线真身等判据收敛为一套共享工具（reviewer bench 为真源，
   figure 经调用复用；跨 pod 拷贝件删除）；
3. **方法学沉淀**：「删文字版取框线掩码（置白版假阴性、差分版漏线核）」写入该工具
   docstring 与量表判定法一句（#176 已落 v0.4.1 词表，此处补工具侧）。

success_criteria:
- 改图后不重生成缓存直接跑 `rev_cover.py` → 自动重生成或明确报错（不再假读数）；
- 「墨迹∩彩色」判据仅一处实现（grep 两 pod 无同功能脚本并存）；
- 方法学说明在工具 docstring 可查；全量绿。
