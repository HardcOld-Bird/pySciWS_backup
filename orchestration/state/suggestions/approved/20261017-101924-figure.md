场景与易错点：`pysci-figures overlap` 在 600 dpi 大尺寸成品上极慢且**无进度输出**——本图 4204×3118 px，单次判据耗时约 **8–10 分钟**（本会话实测跨多个回合）；配合 stdout 重定向时的块缓冲，进程看起来像「挂死」，我因此先后起了 3 个重复后台任务、并误判为缓存过期各一次。当前阈值/蒙版计算是全图 `O(N)` + 分块最近距，缺阶段提示与可选的降采样口径。

期望形态（任一即可）：
1. 逐阶段打印进度（`读到 A/W → 蒙版 → 交集 → 最近距 → 汇总`），并在 CLI 帮助注明「4k 级成品约需 N 分钟」；
2. 提供 `--downsample {1,2,4}`（默认 1）并在报告头标注实际尺度——大图先粗判、细判再全分辨率；
3. `--white` 新鲜度判定同时接受「两版同一次渲染」的显式声明（如 `--same-run`），避免重渲染后误报 rc=2。

success_criteria:
- 对 ≥4000 px 宽成品，`overlap` 运行期间至少每 30 s 输出一行阶段进度（可由重定向日志 tail 观察到），且 CLI `-h` 中出现耗时量级提示；
- 提供并实测 `--downsample` 参数：同一对图在 `--downsample 2` 下给出与全分辨率**同判**的结论，耗时降至 ≤1/3；
- 报告头明确写出所用尺度（px 与 dpi），使「min 距 ≥10 px @600 dpi」判据可复算。
