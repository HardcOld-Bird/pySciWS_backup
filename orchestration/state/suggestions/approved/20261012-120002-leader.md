# 改进建议（leader，待审批）

**（E4，REFACTOR v1.0 §8/§3）bencher 组员 pod：harness 实测专职工（FIFO 队列/套件所有权/基线捕获/副本 A/B/择机通知）**

kind: usability
success_criteria: 见文末。背景与授权：REFACTOR v1.0 定稿（用户终审），E2 已
交付套件与 eval run 机械（d18c49b），本单建「专职测试员」承接运行职责。

规格（REFACTOR §8 全文为准，要点）：
1. pod `orchestration/pods/bencher/`：charter（权限面=对 `state/evals/**`
   完全写权、外部代码树零写权、harness 只读层保护）、专属技能真本（manifest
   + 部署）、`pysci-bench` CLI（`src/pysci/skills/bencher/`，pyproject console
   script——注意 #61 的 uv sync 配方）、registry 注册（flash 默认，压测跑
   minimum 由任务参数指定）、guards 接线；doctor 十二 pod。
2. **FIFO 队列 + 进程生命周期类 devops**：`state/bencher/queue.json` +
   `state/bencher.lock`；`pysci-orch bench-up`（或 approve 联动）拉起分离
   worker；非空消化、空即销毁（非常驻）；stale 锁回收 + 孤儿条目重置；
   run 日志/`.done` 落 `state/bencher-runs/`。
3. **任务面**：入队项=一次套件运行（case 列表）/ 基线捕获（case+worktree ref）/
   副本 A/B（两 ref 或 worktree+main）/ 组长或 inspector 指派的核查跑。
   执行复用 E2 的 eval run 机械（共享库调用，不复制实现）。
4. **择机查看型通知**：完成项写 status 可见的「待查看结果」面（不即时唤醒
   组长——REFACTOR §5.1-B 约定），watch 事件类型 `BENCH-DONE <run>` 可选
   挂载（默认不挂）。
5. **二元判决 + 回退识别**：输出统一「改善/未改善、通过/失败」；窗口期污染
   检查（基线与实施后之间 git 历史含其他 harness 面提交→ inconclusive +
   escalate=twin 标记，taste 未启用则挂起留痕——与 jury 同模式）。
6. **基线捕获**：选 M 时（E5 判决包接口预留 `bench capture <case>` 命令面）
   HEAD worktree + pods gitignored harness 文件归档 →
   `state/evals/baselines/<case>/`（细则实测定，REFACTOR §13 待决 2）。
7. orch eval run 保留（组长抽检面），套件所有权文档移交：README 相应行 +
   devops/bencher charter 职责分界（src 测试 vs harness 测试）。

success_criteria：
- doctor 十二 pod 全绿；`pysci-bench` 可用；队列注入「跑 fig-basic+lit-arxiv」
  → worker 自动拉起→消化→销毁，结果进 status 待查看面（全程无人值守）；
- 一次副本 A/B 真实对比（任选近期两个 harness commit）输出二元判决且
  git worktree 零残留；
- inconclusive 污染检查阳性用例；evals.jsonl 新行带 runner=bencher 字段；
  全量套件无回归。
