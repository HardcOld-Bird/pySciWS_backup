# 改进建议（leader，待审批）

**（E1，REFACTOR v1.0 §2/§2.4）Tier A 失败标签全链：词表+tags 解析+by_failure 统计+阈值自动立案**

kind: usability
success_criteria: 见文末判据。背景与授权：REFACTOR v1.0 定稿 + 用户 2026-10-11
委托（自主推进，见 §15）。

规格：
1. `orchestration/state/failure-tags.json`：受控词表初始集
   `whitelist_conflict, cli_missing, doc_stale, tool_bug, harness_gap,
   model_capability, quota, env_broken, design_smell, unknown`；增补须附定义
   （文件头注释说明纪律）。
2. 交付协议：`<blocked>` 块可选属性 `tags="a,b"`；delivery-gate：属性存在时
   校验词表合法性（非法 → exit 2 + 精确整改指令；缺省合法 = 空列表不阻断）；
   阳性用例（node 直跑真 guard，承 20261010-193601 教训）。
3. delivery.py/dispatch 解析：tags 入 `deliveries.jsonl` 新字段 `tags`；
   `orch ledger` 行渲染显示。
4. `orch stats` 增 **by_failure 段**：标签×成员计数，滑窗参数
   （days/hops）从 registry 读取；`--days N` 复用现有过滤。
5. §2.4 阈值自动立案：registry 参数 `tier_a: {window_days: 14, window_hops:
   20, threshold: 3}`；orch 在 status/approve 入口机械重算，同一
   (tag, member) 越限 → 自动注册 backlog 提案（kind=defect，
   source=tier-a，证据=相关台账行引用，summary 含计数）；**去重**：
   立案指纹（tag+member+窗口桶）落 `state/tier-a-filed.json`，同指纹
   24h 内不重复立案；E5 inspector 流程落地前的衔接：自动提案进 backlog
   后走现行组长 approve 面（orch status 提醒呈现，不新增人工检查点）。
6. charter 真本交付协议段补 tags 一句话说明 + `orch skills sync`；
   orchestration 技能真本同步（≤8KB 预算内）。

success_criteria：
- 构造 `<blocked tags="cli_missing">` 交付 → 台账行含 tags；非法 tag →
  gate exit 2（阳性用例全绿，`orch-tests` check 通过）；
- `orch stats` 出现 by_failure 段且与台账一致；
- 注入 3 条同 (tag,member) 14 天内台账行 → `orch status` 自动立案
  source=tier-a 条目，重复运行不产生第二条（去重生效）；
- 全量套件无回归。
