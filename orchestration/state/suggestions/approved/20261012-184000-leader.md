# 改进建议（leader，待审批）

**（缺陷类）worker 崩溃接管不杀旧派生会话：孤儿 devops headless 与重派新会话并发写同一 worktree**

kind: defect
证据链（2026-10-12 实测）：
- 18:11 worker(pid 9052) 死于批次 164600(+3) 在途——其派生的 headless devops
  会话进程**未随 worker 死**（独立进程树），仍在原 worktree 写入；
- 18:28:10 新 worker(182808) 接管：回收孤儿条目、`worktree remove --force`
  （rc=0）后**重建同名 worktree** 并重派同单；
- 18:35:45 新会话以 25 轮实读发现「同一 worktree 出现并发写入者，本会话零
  成功写入」主动停手 `<blocked>` 上报（停手判断正确，值得肯定）——旧会话
  尚未自然退出，两套写入正相交。

根因：接管逻辑只回收「锁/条目/worktree 名」三面，缺第四面**进程**——孤儿
headless 会话仍是活的写者。

修复面：
1. 孤儿回收时按 run 的会话归属（registry 会话池 sid ↔ dispatch 记录 pid）
   **判活并终止**旧 worker 的后代会话（终止前留日志行；杀不掉则退化为
   「隔离重建」：新 worktree 用 `<id>-r<世代号>` 名，禁止同名并发双写）；
2. `git worktree add` 前加世代守卫断言：同名 worktree 已存在=异常，不得
   remove 后立即假设干净（旧句柄进程可能仍挂在目录上）；
3. 阳性测试：模拟 worker 死亡+孤儿会话存活场景 → 接管后断言旧会话终止或
   新副本异名（两套机制各钉一例）。

success_criteria：
- 构造孤儿会话场景单测绿（终止路径与隔离路径都覆盖）；
- 下一次真实接管（或重派 #68 时）run 日志出现第四面回收行或异名重建行，
  不再出现「并发写入者」报告；
- 既有回收/迟滞/黑匣子行为不回归；全量无回归。

处置注记：本单落地前 #68 保持 needs_leader 不重派（防再次双写相撞）。

**范围扩充（组长 12 日 19:3x，同源第二现场）**：#69 (E6b) blocked 报告了
该盲区的会话池面——**两个进程同时持有同一 devops 会话 sid（6f0cc8e5…）**：
批间 dispatch 默认 resume 最近会话，而上一会话进程尚未退出 → 双进程共写一个
会话历史。本单修复面追加：
4. dispatch 前对目标 sid 做**进程在途核对**（上一跳记录 pid 判活）：仍活则
   等待其退出（有限秒）或自动开新会话并在台账标注 `sid_new_reason=prev_alive`
   ——禁止双进程同 sid 并发；
5. 观测配套（本次两案共同暴露）：blocked 交付**全文必须落 outbox 审计副本**
   （`pods/<m>/outbox/delivery-<ts>.xml`），needs_leader note 保存**不截断**
   全文（截 200 字让两案关键证据都变残片，违背 §0.4 留痕原则）。
