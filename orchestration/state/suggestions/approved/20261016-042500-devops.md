# 改进建议（devops，待审批）

kind: defect
delivery: leader-reflection
来源：组长追查 rv 二连 run_failed（tool_use）定案（2026-10-16，用户点名追查）

**场景**：run_failed 的错误正文只给 stop_reason 短码（`tool_use`/`stop_sequence`），
追查须翻原始 qoderclicn 日志猜根因；且 `tool_use` 终止不触发自动重试，靠人工重派。

**证据（复现 → 实际 → 期望）**：
- 追查定案（rv 二连死+一活）：错误正文=`tool_use` 系 `dispatch.py:1562` 的
  `err_text = (err.strip()[-400:] or env_json.stop_reason)` 兜底——stderr 空时只剩
  stop_reason 短码；第一现场含 `Error executing tool unknown`（模型发出畸形工具调用
  =无名工具），发生于 30k 字符工具结果+多批大图读取之后（重多模态长上下文诱发）；
  第三派换 minimum 席+「输出重定向/分批读图」缓解即过。历史 5 起 run_failed
  （devops-084620=`stop_sequence` 等）同属「stop_reason 透传」家族。
- 自动重试面：`dispatch.py:228` 仅 `envelope_parse_failed` 或 `num_turns==0` 触发
  重试；`stop_reason=tool_use`（mid-run 畸形工具）**不重试**，同指纹人工二连败。
- 期望：错误正文可自足追查；mid-run 失败有自动重试兜底。

**建议**：
1. **错误正文增强**：stop_reason 短码之外附「末 N 条工具调用名+结果状态」（如
   `末3：Bash(ok)/Bash(err)/<unknown>(malformed)`）与 num_turns、是否已重试；
   或把 failure_classes 分类结果一并标注（tool_use/stop_sequence → 新 pattern 类
   `model_glitch`，与 quota/bandwidth/outage 区分）；
2. **重试面扩展**：`run_failed` 且 `num_turns>0` 且 stop_reason ∈ {tool_use,
   stop_sequence} → 自动重试一次（可选换 minimum 席），复用既有首跑重试通道；
   重试仍败才落 failed 留档（留档注明两次 stop_reason）。

success_criteria:
- 构造/复现一例 stop_reason=tool_use 失败，留档错误正文含末条工具调用形态与
  num_turns（不再只有一个短码）；
- mid-run tool_use 失败自动重试一次（日志可见），二次失败才 failed；
- 分类词表若增 model_glitch 类，pattern 附 definition；全量绿。
