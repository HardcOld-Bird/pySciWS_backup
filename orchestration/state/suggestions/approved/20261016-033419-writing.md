① kind: usability（闸约定与任务书目录约定冲突，逼出重复落盘）
场景：任务书本单指定「渲染 PNG 全套落 `20261015/render/`」；而 `registry.json` 的 `pptx-visual` check 是 `pysci-compose slides verify {path}`，不接受目录参数，`verify` 按约定只认 `<pptx 同目录>/<stem>_render/`。
复现与实测（确定性）：
  $ uv run --no-sync pysci-compose slides verify 'data/research/1_gain_ep/汇报PPT/20261015/20261015.pptx'
  [slides verify] FAIL …：幻灯片 7 页 / 渲染 0 张（…/20261015_render）
      ✗ 缺渲染：未找到逐页渲染 PNG（…/20261015_render）
  EXIT=1
  $ pysci-compose slides verify '…/20261015.pptx' --render-dir '…/20261015/render'
  [slides verify] PASS …：幻灯片 7 页 / 渲染 7 张
即：按任务书落盘 → 注册闸 FAIL；按注册闸落盘 → 违任务书。本次被迫 `--out render/` 后再整套复制到 `20261015_render/`（双份 ~5 MB）。
期望形态：让 check 能指向任务书声明的目录——registry 的 `pptx-visual.cmd` 支持 `--render-dir {render_dir}` 占位（派发侧从交付清单填），或 `verify` 在默认目录为空时回退探测 `<pptx 同目录>/render/` 等同义约定名。`compose slides render` 已在输出里打印「可直接粘贴的 verify 调用」，把这条链闭合即可。
success_criteria: 任务书指定非默认渲染目录时，注册 `pptx-visual` check 若能直接 PASS（无需交付方额外复制一份渲染图）即认为达成。

② kind: usability（`geometry` 对连接符用 bbox 判越界，产生必错报的假阳性）
场景：`slides geometry` 的 `off_canvas` 判据取形状 bbox。PowerPoint 为 `bentConnector3`（肘形连接符）存的是「能容纳折线路径」的包围盒，路径本身常远小于 bbox，于是出现报告的越界在渲染图上不存在。
复现与实测（确定性）：
  $ pysci-compose slides geometry 'data/research/1_gain_ep/汇报PPT/20261015/20261015.pptx'
    第 3 页：外框 矩形 5 (0.60,1.34)-(12.66,7.06)（auto）
        越出画布: 肘形连接符 46(4.50,2.33,5.64,8.20) 越出画布：下 0.70in
  复核：取 `render/page-003.png` 的 x 4.30–5.90 in × y 6.30–7.50 in 放大 3× → 区内只有两只虚线子框的下边与模板外框底线，**无任何连接线**（该页是源 deck 末页的整页复制，源 deck 同形状在 i3 校准中亦未被列为溢出项）。
期望形态：`off_canvas`/`off_frame` 对连接符类形状（`bentConnector*` / `straightConnector*`）改用实际路径端点（或 `a:off`+`a:ext` 结合 `flipH/flipV` 还原折线端点）判定，或将其单列为「提示」不计入 `violations`——否则「零容忍」验收会把这一项当成真缺陷，逼交付方去改本不该改的源形状。
success_criteria: 对 `20261015.pptx` 复跑 `slides geometry`，页3 不再出现该条越界（或明确标注为「连接符 bbox 提示、非违规」），而同一命令对真正越界的图片仍照报。
