# 改进建议（devops，待审批）

kind: defect
success_criteria: 在 main 上按新配方执行「pyproject 新增 console script → uv sync」，`.venv/Scripts/` 中 [project.scripts] 声明的入口一个不缺（含 pysci-orch/pysci-dev/pysci-mirror），且失败时不出现「其余入口已被删除」的半坏态；devops 技能 references 里有该配方的落点。

摘要：`uv sync` 在 Windows 上遇到「运行中的 exe 被占用」时，会**先把同一 Scripts 目录下其余入口删掉再失败**，留下半坏 venv——症状是 sync 报 `failed to remove file ...pysci-orch.exe: 拒绝访问 (os error 5)`，随后裸 `pysci-dev`/`pysci-figures`/`pysci-compose` 等集体 command not found，容易被误诊成 PATH 或安装问题，且会让正在进行的 drain 会话全部失去工具面。

复现（本机 2026-10-12 实际发生）：
1) 组长侧挂着 `pysci-orch.exe watch --timeout 14400`（PID 22676）；
2) `pyproject.toml` 新增 `[project.scripts] pysci-mirror`；
3) `cd <root> && uv sync` → `os error 5` 失败；
4) `ls .venv/Scripts/pysci-*.exe` → 除被锁的 orch 外多个入口已消失（实际输出：pysci-dev/imagine/compose/figures/model3d MISSING）。
期望：sync 失败应整体回滚（不半途删入口），或至少把「被谁锁住 + 恢复步骤」写进错误输出。

临时对策（已验证可行，建议固化为 devops 技能配方）：`wmic process where "ProcessId=N" get CommandLine` 确认占用者 → **重命名**被锁 exe（Windows 允许重命名运行中 exe，不允许删）→ 重跑 `uv sync` → 入口全数重建 → 事后删 `.locked-*`。切勿 kill 组长进程（越权且阻塞 drain）。本次已按此法恢复，残留 `.venv/Scripts/pysci-orch.exe.locked-20261012`。
