# 夜航 OFF 态注入应为零：刹车差分文案暗示「等待用户」（用户实测反复验证）

kind: defect
source: leader
fingerprint: night-off-injection-wait-hint-20261017

## 现象（实证，用户 2026-10-17 裁决）

夜航**关闭状态**下仍有提示词注入（`NIGHT_DIFF_OFF`，开→关差分经 watch-arm rewake 注入
下一轮），其文案「恢复与用户的一问一答」「决策权回到用户」「该问用户的照常问」实测
**反复**暗示 LLM 在推进前等待用户回复——与「本项目始终鼓励自主推进」直接相悖。该
文案 2026-10-15 已按用户裁决改写过一轮（禁「立即停止自主推进」字样），但「恢复一问
一答」框架本身仍在产生相反暗示。用户裁决（2026-10-17）：**关闭状态不要注入任何提示词**。

## 必要性核查（结论：无确切必要）

1. 授权回收已自助：NIGHT_POLICY 原文自带「本授权随 [night] enabled=true 有效，关闭即
   失效」——授权自限于开关状态，无需另行刹车；
2. AskUserQuestion 拦截按开关**每回合现读**（night-gate.sh），OFF 自动放行——行为面
   已随开关恢复，无需文字告知；
3. 残留风险（模型带旧授权进新回合）远小于「暗示等待用户」的行为代价（用户实测前者
   未观察到、后者反复观察到）。

## 修法

- **OFF 态零注入**：`diff_message` 的「开→关」分支返回 None（与无变化同路），
  `NIGHT_DIFF_OFF` 常量删除；仅保留「关→开」注入 NIGHT_POLICY（热生效价值保留）；
- SessionStart/PostCompact 的 OFF 路径本就零注入，不动；
- 测试改断言：「ON→OFF 跳变 → --diff 零输出」（原断言刹车文案的用例随修）；
- 文档同步：night.py 模块注释、SKILL 夜航速查、patrol-watchdog.md §5 中「刹车差分/
  恢复一问一答」类措辞清除，明写「OFF=零注入零暗示」。

success_criteria:
- 拨动 enabled=true→false 后 `night --diff --session X` 输出为空（stdout 零字节）；
- enabled=false 的 SessionStart/PostCompact 依旧零输出；enabled=true 注入全文不变；
- 代码与文档中无 NIGHT_DIFF_OFF 残留、无「恢复一问一答/可等待」类措辞；
- 回归测试：ON→OFF 零输出一例＋OFF→ON 注入一例；`uv run --no-sync pytest tests` 全绿。
