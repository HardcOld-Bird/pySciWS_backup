# 改进建议（devops，待审批）

kind: defect
delivery: leader-reflection
来源：组长工作摩擦反思（2026-10-15 第四轮）

**场景**：与某计划无关的 orch 命令（plan advance / taskbooks link / report / sync 均触发）
会**重写全部 plan YAML**（纯折行重排），反复弄脏跟踪 state 面——每次命令后环境提示
「previously read file(s) changed: rework-smooth-20261015.plan.yaml」，且该文件累积
4+/2- 的无语义 diff。

**证据（复现 → 实际 → 期望）**：
- 复现：对 tb-3/rework-tb 计划跑 `plan advance`/`taskbooks link` 等（从未编辑过
  rework-smooth-20261015.plan.yaml）。
- 实际：`git diff rework-smooth-20261015.plan.yaml` = 仅 brief 字段折行变化（4 insert,
  2 del，语义零变化）；命令输出尾随「1 previously read file(s) changed」；`orch status`
  的「跟踪 state 脏面」长期列多份 plan 文件。危害：脏面会挡组员合并前检查
  （「派发碰同文件的单前先提交或还原，否则组员只能交 blocked」），且与 #172（手编折行
  摩擦）同根——工具重序列化是折行漂移的源头。
- 期望：不改的文件字节不动（序列化稳定），或运行时状态只写 `.state.json`、蓝图
  YAML 仅在人为 plan amend 时落盘。

**建议**：①plan YAML 重写仅发生在真实变更（plan new/amend）时，读路径不做 normalize
落盘；②若确需 normalize（如 lint 修复），仅写有变化的文件且保持原折行（或 round-trip
保真）；③回归测试：连续执行 N 个无关命令后 `git diff state/plans/` 为空。

success_criteria:
- 对 A 计划执行 plan advance/taskbooks link/report/sync 后，未编辑过的 B 计划
  `.plan.yaml` 字节不变（hash 断言）；
- 全量绿；`orch status` 脏面不再因运行时 normalize 列出 plan 文件。
