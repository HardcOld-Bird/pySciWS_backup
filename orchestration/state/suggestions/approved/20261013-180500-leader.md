## 规格

### 1. 优先级表（配置面，改动归用户）
`data/pysci_settings.toml` 新增 `[priority]` 段（缺省如下，字符串可改）：
1. `leader`（TUI 会话——不管；用户手动）
2. `research`（7 专职 + reviewer + deputy）
3. `devops`
4. `bench-pressure`（bencher 派生的 minimum 压测会话——比 bencher 本体高档，
   因它产生更多会话）
5. `bencher`、`twin`
6. `inspector`
（仲裁团独立按量渠道，不入表）

### 2. 共享活跃会话注册表
`state/active-sessions.json`（运行态）：各 worker 在跳开始/结束写
`{worker, tier, purpose, sid, started, updated}`，心跳随跳内推进刷新（>10min
无更新视为死条目，与 pid 判活互校）；读侧供仲裁器与 status/mirror 展示。

### 3. 延期机制（带宽类失败的主处置）
- 失败先过分类器（A）：`bandwidth` → **延期路径**（不换席、不回退）；
- 延期动作：项目**回队 pending** + 指数退避（`defer_until` = 2→4→8→…分钟），
  事件入 run 日志 + mirror（"带宽延期"可见）；
- **延期预算**：单项 ≤6 次 或 累计 ≤30 分钟（registry 可配）——超预算才落
  回退链（或对 devops 落 needs_leader）；
- **不占槽**：延期后 worker 继续吃下一项；全队皆未到期待重试时，worker
  **睡到最近到期时刻**（进程级 sleep，零 token；上限如 10 分钟）再查，
  循环至到期或有新任务；
- `outage` → 走 #105 同席重试（10 次+壁钟预算）→ 链回退；
- `unknown` → 二级判据：**存在更高优先级活跃会话 → 按 bandwidth（延期）；
  否则按 outage（回退）**（用户的核心提议）。

### 4. 预防面（轻量，主防线仍在失败后分类）
- `bench-pressure` 派发前置检查：tier2/3 活跃 → 短暂延期（不抢带宽）；
- inspector 已有让路（沿用）；bencher 本体沿用异步面板。

### 5. #105 接线（避免二次改同一处）
`channel_error` 处置改为：分类器 `bandwidth`→延期（本单）；`outage`/`unknown`→
同席重试 10 次+预算→链回退（#105 原规格）。两单共享分类器，互不重复。

success_criteria：
- 仲裁器单测矩阵：高优先级在场+bandwidth → 延期不换席；无高优先级+unknown
  → 回退；延期预算触顶 → 落回退/needs_leader；注册表心跳过期条目被忽略；
- 注册表生命周期实测（写入/读取/stale 清理）；bench-pressure 派生会话被正确
  标 tier4（实测一条）；一次构造或真实的带宽类失败 → 端到端延期而非回退
  （台账 defer 事件 + mirror 可见）；worker 睡到到期续跑实测；
- #105 与 A 的用例交叉不回归；全量无回归。

**补充（用户 2026-10-13，浅回退；并单实施）**：**隐性 DeepSeek 态是带宽特例**
——该模式下有**两条主力渠道同时可用**（DeepSeek 付费 + 生效预设的订阅主力），
可混合扩带宽。处置顺序改为：
- 隐性态下 DeepSeek 席 **bandwidth 类失败** → **先浅回退一拍**：试生效预设的
  主力席（mimo 隐性→Mimo-Flash；qwen 隐性→Qwen-Flash BYOK，订阅渠道）；
- 该席**也** bandwidth 失败 → 才**延期**（本单既有延期机制）；
- 非隐性态（普通模式）不启用浅回退（无第二可用主力渠道），沿原判据分层。
实现：routing 的隐性态席链第二席 = 生效预设的原主力席（不落通用 DeepSeek 链）；
带宽分类判据与延期预算共用本单机制。
success_criteria 增补：构造隐性态 DeepSeek 带宽失败 → 一跳内落到预设主力席；
该席仍带宽失败 → 进延期；非隐性态行为不变（对照组）。
