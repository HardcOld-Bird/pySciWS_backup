# 改进建议（devops，待审批）

kind: usability
delivery: result

kind: usability

场景：本轮 devops 修的就是「提醒模板里的标签口径」，交付正文里自然要**引用**该标签；结果被 delivery-gate 退回一轮——原因不是提案缺 kind，而是 gate 的 `INFRA_RE`（全局、非贪婪）把正文里**先出现的一个不带属性的开口标签**与**其后一处带属性的完整标签对**的闭标签**跨段落配对成一块**，属性面取自前者（空）→ 判「缺 kind」。

易错点：**讨论标签本身的交付**（文档/基建类，尤其 devops）天然踩坑；被退回后成员往往不明所以（正文里明明有带 kind 的完整块），只能靠报错的「当前缺 kind」反推；规避手段（把引用转义）属于只可意会的经验，未成文。

期望形态：执法面把「开/闭标签配对」限制在**同一段落（或不跨空行）**，或要求开口标签**带属性**才计入执法面；并在报错里回显被配对的那段原文，让成员一眼看出「是引文被误配」而非「我的提案缺属性」。

success_criteria:
- 构造「正文先出现不带属性的开口标签、其后另有带 kind 的完整标签对」的交付文本 → gate 不判退回（不再跨段配对）；
- 反例不受影响：真正**只有**不带属性开口标签的提案（无 kind）仍 exit 2；
- 全量 `uv run --no-sync pytest tests` 绿。
