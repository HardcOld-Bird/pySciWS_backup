# 改进建议（leader，待审批）

**（E2，REFACTOR v1.0 §3/§1.1）minimum 档设立 + harness 测试套件骨架 + orch eval run**

kind: usability
success_criteria: 见文末判据。背景与授权：REFACTOR v1.0 定稿 + 用户委托 §15。
**护栏级决定登记**：minimum 档经用户裁决创建（REFACTOR §1.1），但型号选择原
属「专门环节」——委托期内组长决定：**minimum 暂映射内置 Qwen3.8-Flash**
（现唯一零成本渠道，限时免费；credits 恒 0 已实锤）；档位抽象保持独立，
E3 SiliconFlow 接入后重估是否引入更廉价的压测渠道。决策已入 preference-journal。

规格：
1. registry：新增 `minimum` 档（models 映射 + 注释注明上述决定与重估条件）。
2. `orchestration/state/evals/harness/`：首批 **3 个套件案**，从真实历史提炼：
   - `fig-basic`：figure pod 出图任务（判据=figure-audit 通过 + 产物存在）；
   - `lit-arxiv`：lit pod arxiv 检索任务（判据=结果含指定论文 ID、交付格式合规）；
   - `blocked-recheck`：曾 blocked 的白名单冲突案改编（判据=不出现
     whitelist_conflict 类失败）；
   每案文件 = 任务书 + 白名单 + 机械判据（复用 checks 注册表）+ 预期指标
   基线（占位首跑后回填）。
3. `orch eval run [--case <id>] [--all] [--model-tier minimum]`：dispatch
   特化封装——全新会话（--session new）、固定 minimum 档、不附审批回复、
   跑完执行案内机械判据 → **二元判决（通过/失败）**+指标行（num_turns/
   duration/est_tokens/ctx_ratio）落 `state/ledger/evals.jsonl`；
4. `state/evals/baseline.json`：`orch eval set-baseline` 以最近一轮回填；
   `orch eval run` 末行输出与 baseline 的 before/after 对比表；改善/未改善
   二元判据 = 通过数不减 且 均值 num_turns 不劣化（首版机械规则，可调）。
5. orchestration 技能真本 + devops 技能真本补 `eval run` 用法两行（预算内）。

success_criteria：
- 3 案文件齐备且各自 `orch eval run --case` 可独立跑通（真实派发，minimum 档
  台账可证）；
- 对一次真实 harness 改动（取 41/42/43 合并后 vs 合并前，或新造）跑
  before/after 输出二元判决；
- evals.jsonl 字段齐备（case、verdict、指标、model）；全量套件无回归。
