# orch 引导文案两处小修：[NEXT] 只推阻塞式 `plan run`；plan new 源文件命名无提示

kind: usability
source: leader
fingerprint: orch-next-wording-20261016

## 现象（实证，2026-10-16 整日 plan 派发使用）

1. `plan new` 与 `plan advance` 的 `[NEXT]` 引导都只写「书写该环节任务书后推进：`plan run <id> --text …` / `plan run <id> --task …`」——`plan run` 是**同步阻塞**式，而技能铁律对长任务的正道是 `plan advance`（入队即返回、事件驱动）。本次 12 个环节每次都要手工把引导里的 `run` 换成 `advance`；新手照 [NEXT] 抄会把长任务跑成阻塞式、撞 Bash 超时（dispatch-playbook 已有同类教训注记）。
2. `command-surface.md` 写「YAML 复制进 `state/plans/<id>.plan.yaml`（源文件登记后可删）」，但没说**源文件勿与目标同名**（同名 copy 行为未知）。实际只能先写 `xxx.src.yaml`、登记后删除，多一次猜测。

success_criteria:
- `plan new` / `plan advance` / `plan run` 的 `[NEXT]` 引导**并列**给出 `plan advance`（标注「入队即返回，长任务首选」）与 `plan run`（标注「同步阻塞到交接」）两种推进方式；
- `command-surface.md` plan new 行补一句：源文件任意位置、登记后可删、**勿与 `state/plans/<id>.plan.yaml` 目标名同名**（或说明同名时的行为）；
- 相关文案测试（若有钉 [NEXT] 字样的用例）同步；
- `uv run --no-sync pytest tests` 全绿。
