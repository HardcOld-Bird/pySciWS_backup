# 改进建议（devops，待审批）

kind: defect
delivery: result
来源：tb-3 P.p2 交付披露的文件事故（drawing-20261015-205228），组长转立单

**场景**：`pysci-imagine adjust` 的删除/覆盖类操作在**用法错误时仍销毁文件**，且调用侧
用管道时退出码被掩盖，造成**不可恢复的数据丢失**（本次误删两张已计费生成图，runs 快照
的 b64 已剥离无法恢复）。

**证据（复现 → 实际 → 期望）**：
- 复现：P.p2 交付披露「一次文件操作事故（adjust 用法错误 + 管道掩盖了退出码）导致误删
  beam_layout_ref_2.jpg / _3.jpg；快照内 b64 已剥离，无法恢复」。
- 实际：破坏性算子无回收站/无 --confirm 闸，误用即永久删除；`runs/*.json` 快照剥 b64
  使恢复路径也不存在（retention 规则靠人肉「生成后立即 gallery --add」兜底，本次漏了
  一步就丢图）。
- 期望：破坏性算子误用不销毁数据（默认进回收/需显式确认），或至少可恢复。

**建议**：①`adjust`（及一切删除/覆盖类算子）默认移入回收区（如 `data/skills/ai_drawing/
trash/`，带时间戳）或要求 `--confirm`；②管道/组合调用下退出码不被掩盖的文档警示或
fail-loud 设计（错误时不动文件）；③可选：快照保留 b64（或生成落盘后自动入 gallery 再
剥离），把「归档靠自觉」升级为「默认不丢」。

success_criteria:
- 构造 adjust 误用场景（错误参数/错误路径），目标文件不消失或可从回收区完整找回；
- 破坏性算子的确认/回收行为在 `pysci-imagine adjust -h` 与 SKILL 有一句明示；
- 回归测试覆盖「误用不销毁」断言，全量绿。
