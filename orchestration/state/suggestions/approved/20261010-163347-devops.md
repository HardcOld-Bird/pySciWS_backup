# 改进建议（devops，待审批）

**基础设施类交付无可路由的机械验收 check**（缺陷类，附证据）。`orchestration/state/registry.json` 的 `checks` 块实测仅一条：`{"figure-audit": {"cmd": ["uv","run","pysci-figures","audit","{path}","--panels"]}}`。于是 orch CLI / guards / pod 只读层这类改动在 delivery-gate 处只能声明 `check="none"`，验收完全依赖 devops 自述测试证据 + 组长人肉跑 pytest——恰是本次任务书要硬化的「能代码硬保证的不靠纪律」同一形状的缺口。建议注册 `orch-tests`：`cmd = ["uv","run","pytest","tests/skills/orchestration","-q"]`（本次自测即该命令，253 例 / 8.75s，成本秒级），供 devops 类交付以 `check="orch-tests"` 声明。

次要同题：`.gitignore` 已忽略 `devops.lock`、`devops-runs/`、（本次新增）`watch.json`，却漏 `devops.cancel`——`orch drain-stop` 若未被 worker 消费即留下未跟踪文件，污染 `git status` 并可能被 `git add -A` 误提交；建议同一策略下补一行。
