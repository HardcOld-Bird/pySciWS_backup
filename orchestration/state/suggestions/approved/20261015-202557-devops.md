# 改进建议（devops，待审批）

kind: defect
delivery: leader-reflection
来源：组长工作摩擦反思（用户指令立单 2026-10-15）

**场景**：`command-surface.md` 把 `plan run` 与 `plan advance` 的旗标写成「两者公共旗标
（以 -h 实测为准）」，但枚举的是并集且与两子命令实测均不符，照文档敲命令直接报错。

**证据（复现 → 实际 → 期望）**：
- 复现：对照 `command-surface.md`「两者公共旗标：--session <latest|new|sid>/--name
  <slug>/--model-tier/--effort/--max-turns/--dirs a,b/--dry/--task <文件>」与
  `pysci-orch plan run -h` / `pysci-orch plan advance -h`。
- 实际：`plan advance` 无 `--name`/`--max-turns`（实测 `plan advance ... --name tb3-i2`
  → `error: unrecognized arguments: --name tb3-i2-infra`，一次派发失败）；`plan run`
  无 `--dry`；`advance` 独有 `--text/--task` 并存、`--evidence` 语义也与 run 略异。
  「以 -h 实测为准」与紧随其后的错误枚举自相矛盾——枚举既然存在就会被照抄。
- 期望：文档按子命令分列各自旗标表（或只写差异面：run 有 --name/--max-turns，advance
  有 --dry），枚举与 -h 一致。

**建议**：修正 command-surface.md 该段为 run/advance 两张小旗标表；顺带核对同文件其他
「公共旗标」类表述（如 review/dispatch）是否有同类并集失实。

success_criteria:
- `plan run -h` 与 `plan advance -h` 的旗标集合与 command-surface.md 枚举逐一一致
  （机械可比对：把两处旗标列成集合 diff 为空）。
- 文档中不再出现「两者公共旗标」式并集表述。
