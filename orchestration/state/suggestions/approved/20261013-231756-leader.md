# 改进建议（leader，待审批）

kind: usability

**背景（本会话两次实证）**：`pysci-dev worktree clean` 只扫**登记在册**（`git worktree list`）的 worktree。但 `.qoder/worktrees/` 下可能存在**未注册的陈旧目录**（不在 list 里，`git worktree prune` 也不动它）——而这类目录恰恰可能藏**未记录产物**：本会话从两个这样的目录里捞回 **2 张遗失工单**（`20261012-194305` → #134、`20261013-022033` → #135）。clean 看不见它们 = 这类遗失面既不清也不报警。

**期望形态**：`worktree clean` 同扫 `.qoder/worktrees/` **目录本身**（不只看 `git worktree list`）：
- 未注册目录 → 单列一档「**未注册**（不在 list）」；
  - **空**目录 → 可清；
  - **有内容** → 「待确认」，并**顶出未记录产物清单**（如 `state/suggestions/*.md` / `state/replies/**` 中不在 main 的文件），供组长先回收再清；
- `--apply` 清空的未注册目录；有内容者需 `--discard`（沿用既有口径）。

**与既有档位的关系**：不改变「已合入 / 未合入 / 待确认」三档语义，只**新增一档扫描源**（目录面），避免「只在 list 里找」的盲区。

success_criteria:
- `.qoder/worktrees/` 下**未注册目录**被 clean 列出（不依赖 `git worktree list`）；
- 空未注册目录 → `--apply` 可清；有内容 → 列「待确认」并列出其中的未记录建议/回复文件；
- 单测钉：造未注册目录（空 / 有内容各一）→ clean 的分档与动作一致。
