# 夜航自动批准「Plan 模式切换」与「Plan 提交审批」＋修正权限弹窗过时定性

kind: usability
source: leader
fingerprint: night-plan-gate-autopass-20261017

## 现象与调研结论（qoder-guide 权威核实，2026-10-17）

用户需求：夜航下 Agent 自主进入 Plan 模式（EnterPlanMode）与提交 Plan 审阅
（ExitPlanMode）两个用户批准环节应自动通过，不因离机卡死。

调研结论（依据官方 permissions/hooks-reference/plan-mode/settings 文档）：
1. **可行性高**：PreToolUse 返回 `permissionDecision:"allow"` 可跳过权限管道直接批准；
   PermissionRequest hook 在弹窗前触发、可代替用户交互返回 allow；`permissions.allow`
   预放行亦属可试路径；
2. **待实测定层**：EnterPlanMode/ExitPlanMode 的批准是否走权限管道（则钩子可接管）
   抑或独立 Plan 审阅 UI（钩子够不着）——文档无明文；
3. **附带发现（过时定性）**：夜航政策文⑥称「工具权限弹窗属硬阻塞、不写钩子接管」——
   与现行文档矛盾（PermissionRequest hook 正是为代替用户批准弹窗设计）。PSEP_2 时期
   的定性已过时，属误导性内容（同 night-off-injection 家族）；
4. 官方无人值守推荐路径是 `auto` 模式（零弹窗）——本单不改会话档位语义，仅在夜航 ON
   时由钩子放行这两个环节，保守可控。

## 实施路径（先实测后定型）

- **实测定层**（qoder-guide 给出的方法）：配 matcher `EnterPlanMode|ExitPlanMode` 的
  PreToolUse 钩子（记 tool_name 到日志）＋返回 allow 的 PermissionRequest hook，TUI 实测
  进/出 Plan，观察是否弹窗、钩子是否被触发；再对照 `permissions.allow` 两规则；
- **按实测选型**：走权限管道 → 夜航 ON 时 PreToolUse/PermissionRequest 对这两工具返回
  allow（读开关，同 night-gate 模式；OFF 恢复人工批准，零行为变化）；独立 UI 层钩子
  够不着 → 如实上报不可行（用户明示「不可以亦可不改进」），并留档官方 auto 模式为
  替代路径；
- **修正政策文⑥**：「工具权限弹窗属硬阻塞」改为「可用 PermissionRequest hook 代替
  用户批准（夜航 ON 时对白名单工具放行）；未覆盖工具仍靠会话权限档位」。
