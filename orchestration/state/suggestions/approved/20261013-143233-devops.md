**缺陷 1：`pysci-dev worktree merge` 的 cp 备份 `*.bak-<ts>` 未被忽略，已污染跟踪面**
- 障碍现象：合并时 state 运行态文件的 cp 阶段生成 `*.bak-<时间戳>` 备份，落在 `orchestration/state/`——既不在 `.gitignore`，也不在排除后缀里（`dev.MERGE_STATE_EXCLUDE_SUFFIXES` 只排除 `.lock`）。于是每次合并都往 main 丢一个未跟踪脏文件，而它正是下一次合并的「交集」候选，与本单两项（停链 + 交集交付形状）自相矛盾：我自己的合并刚留下 `sessions-runtime.json.bak-20261013T142142`（当前 main `git status` 可见）。
- 复现命令与实际输出：
  - `git ls-files | grep -c "\.bak-"` → 实际 `6`（期望 `0`）
  - `git ls-files | grep "\.bak-"` → 6 个 `orchestration/state/{sessions-runtime.json,watch.json}.bak-*`，已提交进仓库
  - `grep -n bak .gitignore` → 无匹配（规则不存在）
- 期望形态：备份后缀并入 `MERGE_STATE_EXCLUDE_SUFFIXES` 或写进 `.gitignore`（`orchestration/state/*.bak-*`），并清掉那 6 个已跟踪者。

**缺陷 2：`test_tracked_registry_is_ordered_chains` 把跟踪面「此刻读数」当断言基准**
- 障碍现象：测试钉死 `face["mimo"]["main"] == [MIMO_FLASH_UUID, BUILTIN_FLASH]`，于是任何一次合法的席位链变更（本例 `987f80c` DeepSeek 插入）都把它变红，且红在合并后的 main 上——把「配置面的授权变更」误报成「代码回归」。这正是 devops 侧已登记的教训「回归测试别锁运行面当前值」。
- 复现命令：`PYTHONPATH="<repo>/src" uv run --no-sync pytest "<repo>/tests/skills/orchestration/test_flash_channel_swap.py::test_tracked_registry_is_ordered_chains" -q`
- 实际输出：`At index 1 diff: '1a54cc57-e614-4521-80cc-447de31dc896' != 'Qwen3.8-Flash'`；`1 failed`。在 `458bc11`（本次合并之前）复现同一失败，故与本单改动无关。
- 期望：锁代码默认（`presets.py` 出厂表）+ 断言「跟踪覆盖若存在则须为授权形态」，并配「跟踪面被非法改写时变红」的阳性用例，而不是断言 registry 的此刻内容。
- success_criteria: 席位链发生一次授权变更后该测试仍绿；同时存在「跟踪面非法改写」时被咬的阳性用例；全量回归无新增失败。
