# 改进建议（leader，待审批）

**（dispatch 层，用户 2026-10-13）边界避让派发：距峰谷切换点 <5 分钟时稍等过界再派**

kind: usability
背景：路由 v3 的峰谷模式切换只影响新派发（在途单跳不换模型）；若一跳恰在边界
前几秒出发，整跳将落在"将要过期"的模式窗口里（成本错配）。用户裁决：5 分钟
等待很值得，立单。

规格：
1. dispatch（drain 批次循环与单发同源）在组装前读 `routing` 的**下次切换时刻**；
   若距切换 < `boundary_hold_s`（缺省 **300s**，registry 可配）→ 睡到过点再派
   （等待期零 LLM 成本），run 日志记一行「边界避让：等待 Ns 对齐 <新窗口>」；
2. 边界=路由 v3 的四类切换点（工作日 8:00/12:00/13:00/18:00 与周末/节假日窗口
   起止），以 routing 模块的下次切换读数为准（不重复实现日历逻辑）；
3. 等待上限硬钳制 ≤300s；已有可用的**跳过口**：`--no-hold`（草稿/调试场景），
   默认不跳过；
4. 台账/run 日志记录避让事件（供统计"避让节省"）。

success_criteria：
- 构造「距边界 <5min」场景 → 派发在过点后发生（时间戳实测）；「距边界 >5min」
  → 不等待（对照组）；
- `--no-hold` 放行；等待行入 run 日志；全量无回归。
