# 改进建议（devops，待审批）

kind: defect
delivery: leader-reflection
来源：组长工作摩擦反思（用户指令立单 2026-10-15）

**场景**：`pysci-orch plan new` 登记含缩进错误的 plan YAML 时，直接抛 Python 原始
traceback，而非可读错误。

**证据（复现 → 实际 → 期望）**：
- 复现：`pysci-orch plan new orchestration/state/plans/x.plan-src.yaml --id x`（x.yaml
  中某叶子 `dirs:` 误缩进为上一行标量的续行）。
- 实际：`yaml.scanner.ScannerError: mapping values are not allowed here` + 10 余行
  调用栈（plans.py:404 → yaml/__init__.py …），exit 1。
- 期望：单行可读错误，如 `[!] YAML 解析失败 <file>:50:9 mapping values are not allowed
  here（常见成因：键缩进层级错误/冒号后缺空格）`，exit 1，无 traceback。

**建议**：`cmd_plan_new`（及 `plan amend` 同面）捕获 `yaml.YAMLError`，打印
problem_mark 的 file:line:col 与一句常见成因提示；顺带可做「叶子字段缩进错位」的
预 lint（本例 dirs:/effort: 比 brief: 多缩进 2 格是典型手误）。

success_criteria:
- 构造一份缩进错误 plan YAML，`plan new` 输出单行错误（含 file:line）且无 Python
  traceback，exit 1；合法 YAML 路径行为不变。
- `plan amend` 对同样坏 YAML 同样友好报错。
