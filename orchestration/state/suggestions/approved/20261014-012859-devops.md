kind: usability
现象：本单白名单为 `src/pysci/skills/orchestration/tools/**`、`tests/**`、`orchestration/state/queues/`，未含 `.gitignore`；但新建运行态目录（`queues/`）不 ignore 就会在首次真实入队时于 main 工作区留下未跟踪文件，正好触发组长合并交集闸（`merge_dirty_face`），迫使 devops 在实施中途走出白名单。我按 bencher（`state/bencher/`）/inspector（`state/inspector/`）既有按目录策略补了 `/orchestration/state/queues/` 与 `/orchestration/state/queues-runs/` 两行。
建议：凡任务书要求「新建运行态目录」，白名单固定附加 `.gitignore`（或规定该运行态目录自带一个 `.gitignore`），免得每个此类环节都要靠实施者自行判断越界。
success_criteria：
- 下一次涉及新运行态目录的 devops 任务书，白名单含 `.gitignore`；或该目录随创建自带 `.gitignore` 文件。
- 可证伪：若下一单同类任务书仍未列 `.gitignore` 且实施者照旧需越界补行，则本条未生效。
