# 改进建议（devops，待审批）

kind: usability
delivery: result

**场景**：本仓有某个**未定位的写者**会给「无领域技能的 pod」（实测 `twin`、`reviewer`）也创建**空的** `orchestration/pods/<m>/.qoder/skills/` 目录——它不属于 manifest 的部署目标（manifest 只覆盖 11 个 pod，主树里 twin/reviewer 也确实没有该目录）。后果：任何「按目录存在性」断言 pod 未被部署的用例，在全套跑时会误红（本次实测：单目录逐个跑全绿、整套跑 1 红，反复定位未锁定写入时机）。
**证据**：`orchestration/pods/*/.qoder/skills` 在主树为 11 个、在该 worktree 为 13 个（含 twin/reviewer，且内容为空 `ls -A | wc -l = 0`）；删除后全套跑仍会重现，子集（devops 233 / orchestration 1756 / ai_drawing+lit 1150 / comsol+doc+plot+theory 267 / research+paths 47，覆盖全部用例）逐个跑均不重现。
**已做的止损**：把 twin 那条断言从「目录不存在」改为「目录无内容」（本单用例面），故本轮不再误红；**写入者本身仍未定位**——如果后续要给 pod 目录面立任何「不存在」型断言，建议先查清它（可能来自脚手架/巡检/部署链的某个 mkdir），否则会重复误红。
