场景：`orchestration/state/skills-deployed.json` 是**git 跟踪**面、又由 `pysci-dev sync` 在**改任一技能真本后**自动重写。实测本单入场时 main 上它已带 `184213` 单 inspector 真本改动的未提交条目——即「改真本」这个动作本身就会在 main 留一个**台账脏项**，而台账又恰是下次「改真本」的单必须更新的共享面。结果：任何改技能真本的单都会被 `pysci-dev worktree merge` 的「提交面 ∩ main 脏面」交集闸拦住（分支内提交台账→必撞；本单只能把它拆成「分支不提交 + 合并后 main 上单独 sync/提交」两笔，且会顺带替上一单补登）。success_criteria：台账更新与合并闸不再互斥——例如把 `skills-deployed.json` 归入合并闸的**降级告警类**（生成物、非人工编辑面），或在 `sync` 后自动提交该文件，使「改真本」保持单笔原子。
