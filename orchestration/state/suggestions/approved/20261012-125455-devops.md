kind: usability

本次缺陷的实际引爆点不是 `uv sync`，而是根 `.qoder/rules/basic.md` §3 推荐的 **`uv run pysci-X`** 兜底范式——`uv run` 会先隐式 sync 项目环境，pyproject 一变就撞运行中 exe 的锁，**工具本体还没跑起来**入口已被删光（main 实测：rc=2、`.venv/Scripts` 少 6 个、裸命令集体 MISSING）。`pysci-dev venv-sync` 已把自救面固化，但公约数里那句「命令不存在时 fallback `uv run pysci-X`」仍是同一根火柴。

建议（改 basic.md §3 属护栏级外的裁决面，须组长转呈用户）：fallback 统一写 `uv run --no-sync pysci-X`，并补一句「改 pyproject 后先 `pysci-dev venv-sync`（入口缺失时经 `.venv/Scripts/python.exe -m pysci.skills.devops.tools.dev venv-sync`，勿裸 uv run）」。细则已在 `orchestration/skills/devops/references/uv-venv-sync.md` §5 落点，组长可直接引用。
