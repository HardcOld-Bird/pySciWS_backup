# run_failed（基础设施类）恢复路径无指引：半成品盘点与续作纪律靠经验

kind: usability
source: leader
fingerprint: runfailed-recovery-gap-20261017

## 现象（实证，2026-10-17 figure B.b2 首次 run_failed 恢复）

figure 跑 109 跳后被 harness 终止（「Background tasks are still running after 600s」），
交付正文为空、错误正文只有终止语。此时**半成品其实已完整落盘**（产物+交付说明全齐），
但没有任何指引告诉组长「先盘点半成品再决定续作」——我靠经验自行「读盘上交付说明→
核对条款→--session new 续作（只核对不重做）」，顺利收尾。若按直觉整单重派，会重做
已有 95% 的工作。dispatch-playbook 有「余量耗尽交回」与「blocked 三选一」，唯独
run_failed（基础设施类失败、交付为空）的恢复路径是空白；成功案例（盘点→不重做续作）
值得固化为清单。

success_criteria:
- dispatch-playbook 增「run_failed 恢复清单」一节（按需档不破 8KB）：①先盘点半成品
  （产物目录/交付说明/管线脚本在盘情况）②半成品完整→续作任务书明示「只核对与正式
  交付、不重做」③会话选择按 capacity 纪律 --session new ④半成品缺失才整单重做；
- `plan advance` 对 run_failed 环节的 [NEXT] 增一行提示「先盘点半成品再决定续作/重做
  （见 dispatch-playbook run_failed 恢复清单）」；
- 回归测试：文案在场断言一例；
- `uv run --no-sync pytest tests` 全绿。
