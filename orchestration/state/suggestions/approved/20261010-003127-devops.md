# 改进建议（devops，待审批）

① 缺陷类——**worktree 内 `pysci-dev sync` 污染 `skills-deployed.json`，合并后 main 报漂移**：

- 现象：在 worktree 内跑 sync 并提交 `skills-deployed.json` 后，合并回 main 再跑 `sync --check` 会对部分技能报源哈希漂移；须在 main 上重跑 sync 重新生成才一致。
- 复现：`pysci-dev worktree add x` → worktree 内 `PYTHONPATH=$WT/src uv run --no-sync pysci-dev sync`（记录哈希 A）→ 合并 → main 上 `pysci-dev sync`（记录哈希 B）→ A≠B。本次实测：document-writing 在 worktree=f97e5e09、main=dbac3b85；另 scientific-plotting/devops/ai-drawing/modeling3d 同样偏移，而 orchestration/comsol-simulation/literature-research/theoretical-computation 不变。
- 根因（已实测定位）：本机 `core.autocrlf=true` 且无 `.gitattributes`，`git worktree add` 把全部文本真本 smudge 成 CRLF；而 main 工作区是**混合行尾**——例如 `orchestration/skills/document-writing/references/digest.md` 在 main 是 LF、在 worktree 是 CRLF（`cmp` 确认仅此文件字节不同）。`sync.tree_hash` 读**原始字节**，故含 LF 文件的技能在两侧算出不同哈希。恰好「含至少一个 LF 真本文件」的技能才偏移，与实测的偏移/不偏移集合吻合。
- 期望：三选一并由组长裁定——(a) 加根 `.gitattributes`（如 `*.md text eol=lf` 或 `* text=auto`）统一行尾，从源头消除 worktree/main 差异；(b) `tree_hash` 改为行尾无关（读字节前规范化 CRLF→LF），使哈希只反映内容；(c) 维持现状但在 devops SKILL.md「worktree 作业规程」明确写死「skills-deployed.json 的最终值必须合并后在 main 上重跑 sync 生成、不得提交 worktree 内 sync 的版本」。我已按 (c) 把该坑蒸馏进 devops AGENTS.md 作为临时缓解，但 (a)/(b) 是更彻底的修复（影响每个涉及 sync 的 devops worktree 任务）。

② 难用类——**6 个新域暂无注册机械验收 check**：charter 交付协议里各域产物目前只能声明 `check="none"`（registry.json 的 checks 表仅 `figure-audit` 一项）。这意味着 sim 的收敛/网格、writing 的 latexmk 零 error、model3d 的 trimesh watertight 等任务书点名的「验收门」当前只靠组员自检 + 可选 reviewer，无 orch 侧确定性脚本兜底。期望形态：devops 后续为各域注册对应 check 命令（如 `model3d-watertight` 跑技能的 watertight 门、`writing-latexmk` 跑编译链零 error 判定），使这些领域门也能像 figure-audit 一样被 orch 自动执行、FAIL 自动回派。此为 Phase 4「战备逐个验收」阶段可暴露的后续项，非本次脚手架阻塞。
