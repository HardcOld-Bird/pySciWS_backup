# 改进建议（leader，待审批）

**（缺陷类，附证据）drain 长驻进程回写陈旧 registry 快照，lost-update 抹掉运行中合并的配置改动**

kind: defect

复现（实测 2026-10-11 首战）：
- 21:05:57 drain worker 启动并加载 registry.json（deputy/reviewer model_tier=max）；
- 21:42:41 E0-C 批次合并 flash+tier_note（commit fcaf08b/07a3cf4，HEAD 正确）；
- 22:04 实测 `git diff HEAD -- orchestration/state/registry.json`：工作树两成员
  **回退为 max、tier_note 消失**（diff 输出即证据：-flash +max）——drain worker
  收尾（写台账/会话池字段）时把 21:05 加载的旧副本整体 save() 回去，后写覆盖。

实际输出：工作树配置 = 合并前旧值（用户已裁决的降档在运行态被无声撤销）。
期望输出：任何进程不得用陈旧全量副本覆盖 state 配置面。

修复要求：
1. registry（及同类 state 写回）改**读-改-写按键合并**：save 前重读磁盘当前
   内容，只覆盖本进程负责的字段（会话池/水位/台账类运行态），配置面
   （model_tier、pod 路径、参数模板等）一律以磁盘为准；或拆为配置区+运行态区
   两文件（参照 20261010 registry-runtime-split 先例，此缺陷即其未尽面）。
2. drain worker 生命周期内禁止全量 save registry——grep 其所有 registry 写点，
   逐一改合并写。
3. 回归测试：模拟「worker 加载旧配置 → 外部合并新配置 → worker 写运行态」
   序列，断言磁盘配置面保持新值。
4. 顺带小缺陷（同批处理）：drain ledger 中 E0-B 条目 `commit=""`，但合并
   commit 实际存在（f2e0840，`git log` 可查）——`_extract_commit` 对该批交付
   正文提取失败。要求：提取失败时回退为「按 worktree 分支名查 merge commit」
   （`wt-<backlog-id>` 纪律），不留空串。

success_criteria：
- 新构造同序列的单测通过（断言配置面不被回退）；
- 下一次 drain 多批次 run 中，若批次合并改过 registry 配置，run 结束后
  `git diff HEAD -- orchestration/state/registry.json` 为空；
- 后续 run 的 .done 里 done 条目 commit 字段非空（提取成功或有明确查不到注记）。

注：本事件已由组长现场处置——工作树 registry.json 已 `git restore` 回 HEAD，
本修复防再发。
