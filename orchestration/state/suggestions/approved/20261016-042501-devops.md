# 改进建议（devops，待审批）

kind: usability
delivery: leader-reflection
来源：组长工作摩擦反思（2026-10-16 第六轮）

**场景**：`pptx-visual` 注册 check 的渲染目录约定僵硬——只认默认 `<stem>_render/`，
而用户明令渲染件落 `20261015/render/`，w1 被迫**维护双份渲染目录**（render/ 与
20261015_render/ 内容重复）才同时满足交付组织与机械闸。

**证据（复现 → 实际 → 期望）**：
- 复现：w1 交付（writing-20261016-032341）实测：「registry.json 的 pptx-visual check
  是 `slides verify {path}`（不带 --render-dir），只认默认目录 `<stem>_render/`，
  两处均已复跑 PASS」——双份渲染产物（7 PNG×2+PDF×2）落盘。
- 实际：交付组织（用户指定 render/ 子目录）与 check 的默认目录约定冲突，无显式
  传参通道，只能复制双份。
- 期望：check 支持显式渲染目录（参数/同目录约定/配置键任一），单份渲染即可过关。

**建议**：`pptx-visual` check 解析顺序改为「显式 --render-dir（若 check 声明支持
参数）→ `<stem>_render/` → 交付声明的 render/ 目录（组装说明/同级 render/ 约定）」；
或最简：check 认 `<pptx 同级任意 render 目录>` 唯一存在即用。回归：单份 render/ 在
自定义位置仍 PASS。

success_criteria:
- 渲染件只落用户指定目录一份时 `pptx-visual` check PASS（不再需要 `<stem>_render/`
  双份）；
- 默认行为兼容（原约定路径仍可用）；全量绿。
