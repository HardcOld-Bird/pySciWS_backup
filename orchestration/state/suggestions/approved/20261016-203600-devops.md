# 唤醒链静默漏报：worktree merge 覆盖事件流 + seq 身份撞车吞事件（s6 收尾无唤醒实锤）

kind: defect
source: leader
fingerprint: wake-chain-seq-rollback-20261016

## 现象（用户点名 + 取证）

2026-10-16 19:55:43 devops job（tui-overhaul-20261016 s6-plans-ui）收尾、队列清空，组长**未收到任何 JOB-DONE/QUEUE-EMPTY 唤醒**（用户原话：「队列空后你没有收到任何通知」，靠人工 `orch status` 才发现）。取证链：

- watch listener **全程活着**（`orchestration/state/watchdog-runs/20261016-141805.log`：19:54/19:59/20:09 心跳 age≈11s、listener=活）——不是聋期、不是被杀；
- 事件已正常入流（`state/events.jsonl` seq=6，19:55:43），但 watch 的 `fired` 账无该条、`.qoder/hooks/watch-arm.log` 19:30:56–20:14:37 无「命中事件」；
- **消费账撞车实锤**：`state/watch.json` `consumed` 含 `JOB-DONE|#6 -> 2026-10-16T00:33:46`（**昨晚旧流 seq=6 事件**的消费身份）；今天 s6 事件回卷后 seq=6，`watch._identity()` 算出同一身份 `JOB-DONE|#6`，`filter_consumed` 判「已消费」**静默吞掉**。

## 根因（两环叠加，单环不致盲）

1. **`devops/tools/dev.py::_cp_ignored_state`（worktree merge 运行态同步）把 worktree 侧 `events.jsonl` 纯 cp 覆盖 main 活流**（main 旧文件仅留 `events.jsonl.bak-20261016T192746`：45 条、seq 到 45；覆盖后流回卷成 seq 1..N 重新编号）。`mirror-seen.json` 同遭覆盖（`mirror-seen.json.bak-20261016T192746`/`…195516` 两枚）。
2. **唤醒去重与水位全是绝对 seq**：`watch._identity` 对流事件 = `f"{name}|#{seq}"`（watch.py:424）；`events-seen.json.ack_seq=51`（10-15 22:37 定格）与 watch 基线 `base.events_seq` 同为绝对序号。seq 回卷复用后：新事件与**早已消费的旧身份撞车**被 `filter_consumed` 吞；`events.unacked()`（seq>51）恒空 → PENDING-WORK 判据④失效、`orch status`「待排空 0」假绿。

复现路径：merge 覆盖事件流 → 旧消费账 `JOB-DONE|#N` 残留 → 新 JOB-DONE 获 seq=N → watch 必静默（当前 s6 即此）。

## success_criteria:

1. merge 运行态同步不再覆盖唤醒链：`events.jsonl`/`events-seen.json`/`watch.json`/`mirror-seen.json` 等列入 `_cp_ignored_state` 排除面（或双向合并保 seq 单调），并有回归测试模拟「merge 后 seq 回卷」。
2. 流事件身份抗回卷：`_identity` 改内容身份（ts+event+subject+内容散列）或 seq 改**持久单调计数器**（不取文件内最大值）；ack 水位与 watch 基线同理保持单调。
3. 端到端回归：构造「merge 覆盖 → 新 JOB-DONE」用例，断言 watch 照常唤醒（现必静默）。
4. `events.unacked()` 在流被重置后不假绿（检测到回卷即自愈或显式告警，不得报「待排空 0」）。
5. `uv run --no-sync pytest tests` 全绿。

证据物：`orchestration/state/events.jsonl.bak-20261016T192746`（被覆盖前 45 条）、`state/watch.json` consumed 账、`.qoder/hooks/watch-arm.log`（19:30:56 挂载后零命中）、`watchdog-runs/20261016-141805.log`（listener 活着）、`state/events-seen.json`（ack_seq=51 vs 流 max seq=6）。
