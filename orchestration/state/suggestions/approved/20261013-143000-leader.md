# 改进建议（leader，待审批）

**（dispatch 层，用户 2026-10-13）channel_error 同席重试先于换席：瞬态中断先自救，付费席降为后手**

kind: usability
背景：Mimo 平台侧算力不足导致间歇 `channel_error`（今日 4 起），当前处置=**直接
换席**（落 DeepSeek 付费）——但该类中断是瞬态的，重试大概率即愈；换席（付费）
应后移为最后手段。

规格：
1. 失败分类处置表增一档：**`channel_error` → 同席重试**（同会话 resume 续跑，
   无工作损失——会话逐回合持久化）；重试次数与退避可配
   （registry.model_fallback 增 `same_seat_retry: {channel_error: 1, backoff_s: 45}`，
   缺省 1 次/45s，fail-open）；
2. `quota_exhausted`（确定性耗尽）**不适用同席重试**，维持直接换席/全局停止；
3. 同席重试**不计入**降级事件面（mirror「渠道回退」只记真实换席）；
   重试事件另记 run 日志 + 台账字段（供抖动频率统计）；
4. 重试仍败 → 沿既有链换席（DeepSeek → 内置）；链耗尽语义不变。

success_criteria：
- 单测：channel_error 首败→同席 resume 重试（不动席位）、重试成功即续跑；
  重试败→换席；quota 不重试；退避参数生效；重试不入回退事件面；
- 真实或构造场景实测一次「中断→同席续跑成功」全链，台账可见重试字段；
  全量无回归。

**补充（用户 2026-10-13，重试次数上调；组长加一道护栏）**：
- `same_seat_retry.channel_error` 缺省 **10**（区间 10~20 皆可），统一适用各席
  （改动量最小；主席与顺位席同值，后续要分化再按 preset 配）；
- **新增壁钟预算闸**：同席重试累计耗时 ≤ `budget_s`（缺省 **1800s**）——超预算
  立即换席。理由：次数闸挡不住「真下线」场景（每次失败若耗时数分钟，20 次将拖住
  串行队列近小时）；双闸并用才能既吃满瞬态抖动、又不被死渠道占住队列；
- 每跳的重试次数/累计耗时入台账（抖动频率与预算触顶的统计面）。
