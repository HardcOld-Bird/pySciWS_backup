# NEEDS-LEADER「已提交未合并」陈旧误报：合并完成后事件才被消费，每例浪费一次对盘

kind: usability
source: leader
fingerprint: needs-leader-stale-merge-noise-20261017

## 现象（实证，2026-10-17 一晚 3 次同款）

patrol 在 job 在途期间检测到 worktree 未合并 → 发 NEEDS-LEADER 事件；job 收尾时自行
合并 → 事件仍留在队列，组长 drain 时读到「已提交未合并，请授权合并」——实测 3 次
（wt-20261017-family-pin-fix、wt-20261016-005506-reviewer、wt-20261017-090108-sim）
**全部是合并已完成后的陈旧报**（git merge-base 验证均已在 main、worktree 已摘）。
每次浪费组长一次对盘核实；与 PENDING-WORK 已修的「已处理未销账」（backlog
20261017-001500）是同款病灶，只是面在 NEEDS-LEADER。

success_criteria:
- NEEDS-LEADER「已提交未合并」事件在**呈现/消费时**做旁证细分：分支已并入 main（或
  worktree 已摘）→ 标「已合并陈旧报」不呈报为待办（status 可留注记）；确未合并才照旧
  唤醒；
- 回归测试：构造「事件在途期间合并完成」断言消费时不再提示授权；构造「确未合并」
  断言照常呈报；
- `uv run --no-sync pytest tests` 全绿。
