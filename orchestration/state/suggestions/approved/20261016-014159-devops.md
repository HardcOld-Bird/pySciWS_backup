# 改进建议（devops，待审批）

kind: usability
delivery: leader-reflection
来源：组长工作摩擦反思（2026-10-16 第五轮，返工审查链实战）

**场景**：审查链「FAIL→回派返工→复审一次→二次 FAIL 升级仲裁」与派发要领「同指纹连败
3 次停止回派升级」两条口径不一：**指纹如何界定、新缺陷是否重置审查链**无文档。本轮
b3 FAIL（Sim. 压图）→ b3r 修复达标但查出**新指纹**既有缺陷（Exp.† 压框线）→ 二裁决处
组长须临场裁量「新指纹=新链、再 FAIL 才升级」——依据只能从「同指纹」字面反推。

**证据（复现 → 实际 → 期望）**：
- 复现：b3r 判 FAIL 时对照 SKILL「审查链：…二次 FAIL 升级仲裁」与「同指纹连败 3 次
  停止回派」——两处计数单位（按轮 vs 按指纹）不一致，无一处定义「指纹」。
- 实际：裁量「b3 指纹已修复验收（三命令过），b3r 的 FAIL 属新发现既有缺陷→重开链」
  并留痕（b3r2 任务书写明「再 FAIL 则升级仲裁」）；裁决正确但属无据临裁。
- 期望：审查链文档明文——同缺陷指纹累计（同指纹二次 FAIL 即升级），新缺陷指纹重开
  「返工→复审一次」链；指纹判定法（同验收命令/同元素/同成因）与留痕要求写清。

**建议**：command-surface 或 verdict-package 的审查链段补一段「指纹口径」：①指纹=
（缺陷元素×成因×验收命令）三元组②同指纹复审再 FAIL→升级仲裁③新指纹重开一次链
④裁量须在复审报告留痕。与「同指纹连败 3 次（机械验收面）」的适用面（机械 vs 主观
审查）也一并划清。

success_criteria:
- 文档含指纹定义与两条计数口径的适用面（grep「指纹」命中 ≥2 处且互相一致）；
- 以本轮 b3→b3r→b2r2→b3r2 序列为样例，按文档裁决结果与实际一致。
