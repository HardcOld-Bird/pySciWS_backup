# 改进建议（leader，待审批）

**（E5a，REFACTOR v1.0 §7/§5.2）inspector 组员 pod：闲时巡检引擎（设计审查 rubric/发现晋升/双队列迟滞/全局开关/让路）**

kind: usability
success_criteria: 见文末。授权：REFACTOR v1.0 定稿。理念=「与用户视角相同但
知识不同」的专业抓虫手。

规格（REFACTOR §7 全文为准）：
1. pod `orchestration/pods/inspector/`：charter（全项目**只读**，产出仅落
   `state/inspector/`；pysci-inspect 自身不在巡检范围〔§0.2 豁口〕、设计审查
   rubric `pods/inspector/rubrics/design-review.md`〔只读层，用户提供三原则：
   社区优先/反冗余/LLM 直觉友好——全文由组长从本轮对话整理入册〕）、技能
   真本+manifest+部署、`pysci-inspect` CLI、registry 注册（flash）；doctor
   十三 pod。
2. **生命周期**：`orch inspector-up` 幂等拉起（分离进程+`state/inspector.lock`），
   **内嵌进 orch 常用命令入口**（status/approve/dispatch 执行时自动尝试，
   受全局开关钳制）；单次激活预算硬上限（registry.inspector 参数：最大跳数/
   墙钟）到顶自停；**让路**：plan run 活跃或 devops drain 忙→仅只读巡检，
   一切派发类动作仅全闲时。
3. **工作循环**（queue-first，空则巡检不退出）：巡检菜单随机=抽跑
   `pysci-bench` 队列提案/doctor 全域/随机 pod transcript 与自维护层抽查/
   预算审计/台账成本曲线异常/随机代码走查/**改进管道自身组件**（§0.2 自
   覆盖）/**设计意图一致性核对**（README/charter/技能宣称 vs 实际行为）/
   设计审查 rubric 三维。
4. **发现管道**：`state/inspector/findings.jsonl`（现象+复现+证据+建议 tag）
   → 机械证据类自动晋升 backlog（source=inspector，附证据，无需判决）；
   判断类经 `pysci-inspect submit <finding> --jury`（共享 jury 库，阻塞裁决）
   approve 才晋升（附裁决）；**inspector 无 override 面**（代码不提供该参数）。
   M 实测选项经 bench 队列提案（E5b 判决包统一接口就绪后接入，本期 J 先行）。
5. **双队列迟滞节流**：监视 devops backlog pending 与 bencher queue 长度，
   任一 > 积压上限（12/6）→ inspector 暂停产出（巡检读侧可继续）；双队列
   ≤ 恢复阈值（8/4）→ 恢复；阈值入 registry，恢复严格低于暂停。
6. **全局开关**：`state/inspector.enabled`（默认 true）；`orch
   inspector-off/on`；关闭时拉起逻辑 no-op。

success_criteria：
- doctor 十三 pod 全绿；`orch inspector-up` 幂等 + 开关 + 预算到顶自停
  三态实测；
- 一次自主发现全程：finding→jury→approve→自动入 backlog（source=inspector）
  →devops 消化→合并，组长介入=0（backlog actor/证据链核验）；
- 迟滞闸：注入积压>12 → paused 标记且不晋升，回落≤8 → 恢复（阈值不等
  配置核验）；非法「override」调用面不存在（代码核验）；全量无回归。
