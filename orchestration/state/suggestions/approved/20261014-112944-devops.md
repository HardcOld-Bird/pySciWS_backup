kind: usability
现象：`pysci-dev push` 已按章程实现为 best-effort + 留痕（`orchestration/state/push-log.jsonl`，「失败不静默」是当初的设计承诺），但**没有任何读数面把连续失败浮出来**。本会话 a1/a2/a3 **三连超时**（每次 `[!] push 超时（25s）——已留痕`），而我只有在交付前手工 `tail` 那个文件时才会发现——提交留在 main 未推送到远端，若无人去读 push-log，远端与本地会无声分叉。
建议：给 push 失败加一个**聚合告警面**——`orch status`（或 `pysci-dev doctor`）读 push-log 最近 N 次，若「连续 ≥3 次失败」就单独报一行（点名原因分布与最后失败时刻）。留痕面保持不变，只补「有人会看到」的这一跳。
success_criteria：
- 存在一条读数：`orch status` 或 `pysci-dev doctor` 在 push-log 呈连续失败时输出显式告警行（点名次数与最近原因），连续成功时无此行。
- 可证伪：把 push-log 造到「最近 3 次全失败」，若该读数不报、仍要人工 tail 才发现，则本条未生效。

> **组长撤销 2026-10-14**：用户裁决 push 失败属常态（代理常态化关闭），告警面不实施；防复发注记已入 devops charter。原建议留档。
