**缺陷：技能文档把「回退席纳入拒庭判据」当规则写着，等于给缺陷背了书——代码与文档同错，改代码时才发现**

现象：`orchestration/skills/orchestration/references/jury-channels.md` 原文「硬规则：**任何席位（含回退席）**型号串含 `qwen` → 拒开庭 rc=2」，`jury-panel.md` 同调。而 `jury.py` 的注释恰恰预警「同族回退席不得上场……会把『该降级』的案子误判成『拒开庭』」——**同一份设施里，注释说不能这样、文档说就这样**。实测（`approve 131505 --jury`）证明注释是对的、代码与文档是错的。这不是本单的孤例：两处文档同时还把规则写死成 `qwen`，而路由 v3（2026-10-13）早已把它相对化为 `producer_family`——**同一次语义变更，代码改了三处、文档两处没跟**。

复现：
```
git log -1 --format=%h -- orchestration/skills/orchestration/references/jury-channels.md
grep -n "含回退席\|qwen" orchestration/skills/orchestration/references/jury-channels.md
```
实际：改前该文件对拒庭判据的表述与 `jury.py` 的实际（错误）行为一致、与 `jury.py` 注释相悖；`qwen` 写死也早于路由 v3。
期望：文档表述与代码语义同源。

**为什么会发生（可机械化的那一半）**：`producer_family` / `jury_panel` 这类**相对化**改造只扫了代码，没有「文档宣称 ↔ 代码行为」的对盘机制。README §6 已有 `intent-drift` 巡检菜单项（「挑一段宣称，用可执行命令核验」），但它是**抽样式**的（随机挑一段），不是**改动驱动**的：谁改了 jury 语义，没人提醒他去看 jury 的文档面。于是「代码改了、文档没改」的系统性滞后只能靠 inspector 偶然抽到。

**期望形态**：改「有文档面的语义」时给一个**廉价提示**而非强制门禁——例如 `pysci-dev mdgen-check`（或一个新 `pysci-dev doc-faces <源文件>`）按一张**极小的映射表**（`tools/jury.py → references/jury-*.md`、`tools/dispatch.py → references/drain-watch.md` 等，十来条）打印「你动了 X，它的文档面是 Y/Z，请对盘」。命中即提示、不阻断；没命中就静默。宁可表小且手维护，也不要自动推断（自动推断必然误报，久了就没人看）。

success_criteria: 修改映射表内某源文件时，该命令输出对应文档面路径（可用单测钉：touch `tools/jury.py` → 输出含 `jury-channels.md`）；非映射内文件零输出。
