# 改进建议（leader，待审批）

kind: defect

**现象（本会话实证）**：`pysci-dev worktree clean` 把 `20261012-164600-leader` 判入「**已合入 main（可清）**」，但真清理时 `git worktree remove` **拒绝**——

```
  → 清理 20261012-164600-leader
fatal: '...\.qoder\worktrees\20261012-164600-leader' contains modified or untracked files, use --force to delete it
[i] 分支删除跳过：cannot delete branch 'wt-20261012-164600-leader' used by worktree ...
  [√] 已清理 3 个；未合入 6 个保留
```

即**分类与动作不一致**：清单说「可清」，真删却删不掉——收尾只完成一半，且不留解释（用户会以为已清）。

**期望形态**（择一，以「分类与动作永不矛盾」为准）：
① 该面**确属安全可弃**（脏的只是构建产物/运行态等哨兵）→ `remove` 带 `--force`；或
② 脏面**可能有意义**（未提交的手写改动）→ **改判入「拒绝」类**并在清单里说明成因（「盘内有未提交改动，留待确认」），不作为「可清」项。

**判据**：任何面，clean 的**分类**与**实际动作**必须一致——不许出现「说可清却删不掉」。

success_criteria:
- 构造一个「已合入 main 但盘内有未跟踪/未提交文件」的 worktree → `worktree clean --apply` 的**结果与分类一致**（要么带 force 真删掉，要么列在「拒绝」类并说明）；
- 复跑本会话的 7 个遗留：每个面的「分类—动作」均自洽（无「可清却失败」）；
- 单测钉「有脏的已合并面」的分支行为。
