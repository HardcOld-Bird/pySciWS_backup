# orch 命令面集中整备：twin/deputy 对称化＋bench/inspector 子树化＋内部命令隐藏（用户点名）

kind: usability
source: leader
fingerprint: orch-surface-consolidation-20261016

## 现象（`pysci-orch --help` 实测输出为证）

当前 46 个顶层入口并存 4 种命名风格，历史遗留明显：

1. **咨询不对称（用户点名）**：`consult question`（副组长，文本参）vs `consult-twin case_file`（twin，案卷参）——同是「咨询」，一个无后缀一个带后缀，参数形态也不同。
2. **twin 相关三命令三风格**：`consult-twin`（前缀）、`taste`（隐语名，help 才说明是 twin 判断）、`twin-review`（后缀）——同一角色的三个通道散在三个命名位。
3. **平铺 vs 子树混用**：`watchdog {start,stop,status}` 是子树风格（好），但 `bench-add/bench-up/bench-queue/bench-seen/bench-stop` 5 个与 `inspector-up/inspector-status/inspector-patrol/inspector-assign/inspector-on/inspector-off` 6 个平铺占顶层；且 **`inspector-up`（拉起 worker）与 `inspector-on`（全局开关）名字只差两字母、语义不同**，help 不读就猜不出。
4. **压测双伞**：`eval {run,set-baseline}`（Tier B 套件）与 `bench-add run|capture|ab|check`（bencher 队列）指同一「压测」域、两个名字。
5. **5 个 `_` 内部命令（`_watchdog-loop/_queue-worker/_drain-devops/_bench-worker/_inspect-worker`）混在 usage 的 positional 列表里**，与用户面命令同列。

## 方案（映射表；标注〔默认〕＝直接实施，〔辨析〕＝按引用文档语义定案后实施）

| 现命令 | 新命令 | 性质 |
|---|---|---|
| `consult <question>` | `deputy consult <question>` | 〔默认〕对称化 |
| `consult-twin <case_file>` | `twin consult <case_file>` | 〔默认〕对称化 |
| `taste <case_file>` | `twin taste <case_file>` | 〔默认〕twin 通道归族，隐语名出清 |
| `twin-review` | `twin review` | 〔默认〕同上 |
| `bench-add/up/queue/seen/stop` | `bench add/start/queue/seen/stop`（up→start 与 inspector 对齐） | 〔默认〕平铺→子树，对齐 watchdog 风格 |
| `inspector-up/status/patrol/assign/on/off` | `inspector start/status/patrol/assign/enable/disable`（up→start＝拉起 worker；on/off→enable/disable＝全局开关） | 〔默认〕子树化＋up/on 辨义 |
| `eval {run,set-baseline}` | 并入 bench 伞（`bench eval`/`bench baseline`）或保留 `eval` 并在 help 与 bench 互注分工 | 〔辨析〕按 references/harness-eval.md 真实语义定案：若与 bench-add run 是同能力两入口按 leader-only §2 合并；若是「leader 亲跑抽检 vs bencher 队列」真分工，则至少统一到单一伞名下 |
| `drain-stop` | `devops stop`（与 `bench stop` 对称；`drain` 本就指 devops 队列） | 〔辨析〕确认无其他 drain 语义后更名 |
| `_watchdog-loop` 等 5 个内部命令 | argparse `help=SUPPRESS` 从 usage/帮助隐藏（功能保留，钩子照常调用） | 〔默认〕清理 |
| `plan run` | 已废（建议单 20261016-220500，在队） | 联动 |

**审查结论「不该动」**（记录在案防过度重构）：`watch`（等事件 listener）与 `watchdog`（监督重臂）名字相近但职责有文档资产、实际使用无混淆，**不改**；`status/plan/next/suggestions/approve/reject/requeue/resolve/review/stats/jury/dispatch/sessions/ledger/sync/taskbooks/queues/events/wake-claim/refresh-models` 语义清晰、风格自洽，**保留**；`suggestions/approve/reject` 归 `suggest` 子树收益低（高频+语义清），**不动**。

success_criteria:
- `pysci-orch --help` 顶层入口数显著收敛（bench 5→1、inspector 6→1、twin/deputy 族收进子树、内部命令不再出现于 usage），且**每条映射表〔默认〕行**的新命令可用、旧命令彻底移除（无需向后兼容，用户明示）；
- `twin consult|taste|review` 与 `deputy consult` 参数形态与 help 文案对称（同为咨询动词、各自注明入参形态）；`inspector start/enable/disable` 的 help 一眼可辨「worker vs 全局开关」；
- 〔辨析〕两项按引用文档语义定案并在交付正文写明依据（harness-eval.md 分工结论 / drain 语义归属），实施结果与结论一致；
- 全部文档与引用面同步更名（**清单显式，防漏**）：技能真本 SKILL.md 命令速查、references/command-surface.md 及其余 references、`orchestration/README.md`（权威设计）、`.qoder/rules/*.md`（如引用）、钩子脚本 `.qoder/hooks/*.sh`、tests；**部署副本经 `pysci-orch sync` 同步**（真本→副本两层都验）；grep 旧名零残留（历史留档/交付正文/建议单正文除外）；
