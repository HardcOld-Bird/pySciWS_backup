# 改进建议（devops，待审批）

delivery: result

kind: usability
现象：本环节的机械验收含「`grep` 禁词零命中」，而实施者为了**断言禁词不出现**，天然想在测试里列出这些字面量——于是 I) 测试自身命中 grep（判据把自己判红）；II) 即便用 `"m3" + " 补"` 拼接，Python **常量折叠**也会把结果折进 `.pyc`，令 `grep`（含二进制）仍命中。我实测两轮才把 src/ 与 tests/（含字节码）清到零。
建议：为 f3 将要立的 **lint 规则**与一切「grep 为判据」的清理任务预置一个约定：① 禁词表一律**运行期拼接**（分隔符取自变量，或 `chr()`/`\uXXXX` 转义）以绕开常量折叠；② 判据避开 `.pyc`（`--include='*.py'` 或先清 `__pycache__`）。可写进编排/任务书模板或 lint 任务的判据说明。
success_criteria：
- f3 的 lint 任务书/规则自带一句「禁词以运行期拼接给出，且判据限定 `*.py`（或排除 `__pycache__`）」。
- 可证伪：若 f3 的 lint 规则或其后任何 grep 判据任务，因「测试/规则自身含禁词字面量或字节码折叠」而把自己判红、需二次返工，则本条未生效。
