# TUI 崩溃根治：行重建与点击竞态（parent=None）＋补运行日志（用户实测 4:48 崩溃）

kind: defect
source: leader
fingerprint: tui-rebuild-click-race-crash-20261017

## 现象（用户实测，2026-10-17 04:48）

TUI 点击 `Static(classes='row-title-cell')` 崩溃退出：
`AttributeError: 'NoneType' object has no attribute 'region'`（textual screen.py:1914
`_forward_event`，locals：container=None、select_widget=行标题 Static）。**本仓无 TUI 运行
日志**，但 traceback 足以定位（纯机理推演＋代码对盘）。

## 根因（已对盘 textual 与本仓源码）

1. textual `Screen._forward_event` 处理 MouseDown 文本选择时：`select_offset` 非 None →
   `container = content_widget.parent`（textual screen.py:1900-1907）→ `container.region`
   （1914）——**控件 parent 为 None 即崩**；
2. parent 何时为 None：控件刚被 `remove_children()` 卸载、尚未重新 mount 的间隙——本仓
   TUI 的行/卡片渲染是**整栈重建**（app.py `_render_detail_cards`：`await box.remove_children()`
   → `await box.mount(*widgets)`，1131/1146 行；`_rebuild_tb_list/_rebuild_rulings_list/
   _rebuild_decisions_list/_rebuild_plans_list` 同型）；
3. 触发窗口：`set_interval(1.0, self._tick_detail)`（700 行）每秒刷新（tui-polish「统一
   每秒刷新」02:11 落地，崩溃 04:48——时窗吻合，疑刷新频率放大竞态概率）；点击恰落在
   remove/mount 间隙时，`get_widget_and_offset_at` 从尚未刷新的视觉映射取到已卸载控件
   → parent=None → 崩。**低概率×整夜长跑×每秒一窗 = 必然命中**。

## 修复面（三层，建议全做）

1. **补运行日志**（用户明示）：TUI 运行日志落盘（如 `data/logs/tui-YYYYMMDD.log` 或
   state 运行态面）——生命周期＋**未捕获异常**（含 traceback）时间戳全记；本次这类
   崩溃今后可直接对日志；
2. **根因收敛**：各 `_render_detail_cards`/`_rebuild_*` 重建前做**内容指纹比对**，未变
   不重建（每秒 tick 多数时候无变化——竞态窗口收敛数个量级＋省资源）；变则照常重建；
3. **崩溃免疫**：TUI 子类覆写 `_handle_exception`（textual app.py:3263，走到 3285
   `_fatal_error` 即退出）——先落日志，对「事件处理竞态」类异常**优雅续命不退出**；
   （可选加固）行/卡片 Static `allow_select=False`，文本复制走 detail_body 文本面。

success_criteria:
- TUI 运行日志在盘（含一次模拟异常注入的 traceback 记录）；
- 内容未变时重建不触发（可测：tick 前后控件实例不变/日志注明 skip）；
- 构造「点击瞬间重建」竞态（或异常注入）：TUI 不退出、日志有记录；
- 修复前崩溃样例（MouseDown 落行标题）复跑不再崩；
- `uv run --no-sync pytest tests` 全绿。
