# 改进建议（devops，待审批）

kind: defect

**（缺陷类）`new_run_log()` 秒级命名可撞名，撞名时「真的活锁」会被 E4 新否决支误判为已收尾残骸**

E4 把「该 run 已有 `.done`」请进判活后，`.done` 的**文件名**成了否决依据，而 run 名只精确到秒：`drain.new_run_log()` = `devops-runs/<%Y%m%d-%H%M%S>.log`，同秒两次调用得到**同名**（`new_run_log()` 只生成不落盘，也不查重）。快速收尾的 run（空队列/仅 lock_busy）在同一秒内写出 `.done`，紧随其后同秒启动的 drain 会拿到同名 run_log —— 它的锁**新鲜、pid 存活、正在干活**，却因那份 `.done` 被判非活。后果：`lock_status` 报 `stale/done-exists`（谎报残骸），且 `acquire_lock` 对它放行 → **两个 worker 同时自认持锁**，README §6 的单 worker 互斥被击穿（E4 之前的秒级撞名只是日志混写，现在升级成互斥失效）。`.done` 摘要侧已要求 run_log 自证同名，挡不住同名本身。

实测复现（只写 Temp 目录，不碰真实 state；main 树 a513bbd，2026-10-11）：

```
cd <main> && PYTHONUTF8=1 python   # drain.LOCK_PATH / DEVOPS_RUNS_DIR 指 Temp
same name reused -> True 20261011-233017.log
B is alive, lock fresh. lock_status -> {"state": "stale", "residue": "done-exists", "crashed": False, "pid": 777777, "age_s": 0.6}
C can steal B's live lock -> True
期望: 活锁 state == running 且 acquire_lock 返回 None（互斥不破）
```
（我本轮的 E4 测试最初就踩中它：接管后断言 `state == "running"` 得到 `stale`，只能改用显式异名 `next-run.log` 才通过——即此格目前靠测试写法绕开，没有代码面护栏。）

修复面：
1. `new_run_log()` 改为**查重生成**：`<ts>.log` 或 `<ts>.done` 已存在时追加计数（`<ts>-2.log`、`<ts>-3.log`…）直到唯一，让 run 身份在同秒内也不重复（保持既有 `<ts>` 前缀，`latest_done()` 的 glob 排序语义不变）；
2. `_run_concluded()` 增加「锁龄早于该 `.done` 的 `completed`」一类的时序核对作为第二道闸（`.done` 只可能晚于它所终结的锁），文档说明与 ① 的分工；
3. 阳性测试：同秒连调 `new_run_log()` 两次必得异名；以及「先落 `<ts>.done`，再以同名生成锁」时活锁仍判 `running`、`acquire_lock` 拒抢（把上面 repro 钉成回归用例）。

success_criteria:
- 上述 repro 在新代码下反转：`lock_status()["state"] == "running"` 且第二个 `acquire_lock` 返回 `None`；
- 新增阳性测试全绿，E2/E3/E4 全套（含 `test_watch_complete_identity.py`）无回归；
- 真实 drain 连跑两轮后 `devops-runs/` 不出现同秒同名（`.log`/`.done` 配对唯一）。
