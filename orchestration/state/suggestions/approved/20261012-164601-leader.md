# 改进建议（leader，待审批）

**（E6b，REFACTOR v1.0 §11 来源②）用户 prompt 语料倒序解析入库 + twin 宪章增量蒸馏草案 v2**

kind: usability
success_criteria: 见文末。背景：用户提供 prompt 总集
（`data/others/prompts_storage/` 三文件，实施时以目录实际为准）；E6-prep 的
PREFERENCE.md v1 仅蒸馏 README §13 + journal 39 条，语料入库是 twin 训练
原料的最大增量源。

语料格式规律（用户口述，脚本须按此实现）：
- 文件**倒序**：开头较新、末尾较旧；
- **连续 ≥2 空行（≥3 个换行符）= 消息分隔符**（上=new 下=old）；
- 单空行/单换行**不是**分隔，仅排版（上方先写、下方续写，同一条消息）；
- 解析后输出**正序**（旧→新）时间线。

规格：
1. 解析脚本（一次性入库工具，放 devops 侧 bench 或 scripts，不定义复杂类
   于 src 之外）：三文件 → 逐条消息 → `state/preference-journal.jsonl`
   追加（source="user-corpus"，kind="prompt"，situation=首行摘要，
   choice=原文全文或截断引用，ts=按倒序还原的相对时序标注+文件锚）；
2. **twin 宪章增量蒸馏草案 v2**：基于 v1 + 语料新样本，由 twin 通道不可用
   （taste 未启用）→ 组长起草蒸馏跳任务书、devops 用 flash 冷启动会话执行
   蒸馏（复用 taste 的派发机械但输出仅落草案文件），产出
   `PREFERENCE.md` v2 diff **草案**（标注「待用户确认」，不动生效面）；
3. 语料含个人表述：入库文件保持 git 跟踪状态与现有 journal 一致，若体积
   过大按既有 .gitignore 细则处理（组长裁量）。

success_criteria：
- 解析规则三例阳性（≥3 换行切分正确、单空行续写不误切、倒序还原抽查 3 条
  与原文对应，测试夹具用构造样本不碰真语料）；
- journal 新增行数=解析消息数（脚本输出对账），source=user-corpus 可查；
- PREFERENCE v2 diff 草案落盘且 taste_enabled 仍 false、生效文件未动；
  全量无回归。
