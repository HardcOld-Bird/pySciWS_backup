# orch 失败/恢复指引误导二处：twin rc=2 语义＋续作会话提示与 capacity 纪律矛盾

kind: defect
source: leader
fingerprint: orch-guidance-mislead-20261017

## 现象（实证，2026-10-17 首次用 twin 与首次 run_failed 恢复时各踩一次）

1. **twin rc=2 语义误导**：SKILL/command-surface 写「`twin consult <案卷.md>`（未启用即拒
   rc=2）」——实测 rc=2 的真实原因是**冷启动纪律拒绝复用会话**（报文「拒绝复用会话
   （session='latest'）」，twin 本身可用，`--session new` 即成功）。若按文档语义解读
   「twin 不可达」，会走夜航降级路径（副组长咨询+自行决断）——**白白放弃 twin 终裁**。
   rc=2 一码两义、文档只写一义，误导性强。
2. **续作会话提示与 capacity 纪律矛盾**：figure run_failed 后 `plan advance` 的 [NEXT]
   写「（本环节会话 982c6a21，续作自动复用）」——但 dispatch-playbook capacity 纪律明言
   「原会话无余量，续作必须 `--session new`」。run_failed 本身就是容量/等待耗尽的产物，
   自动复用大概率再撞墙。两条指引打架，执行端只能靠纪律文档压过 [NEXT] 提示。

success_criteria:
- `twin consult` 失败时报文按因分型（未启用 vs 冷启动拒复用），后者明示「加 --session
  new 重试」；command-surface/SKILL 对应行补注「冷启动须 --session new」；
- `plan advance` 对 failed 环节的续作提示按失败类型给会话建议：run_failed/容量耗尽类
  → 提示「建议 --session new」，内容类补充 → 维持自动复用；
- 回归测试：两条文案各一例断言（含 --session new 字样）；
- `uv run --no-sync pytest tests` 全绿。
