# 改进建议（devops，待审批）

kind: usability
delivery: leader-reflection
来源：组长工作摩擦反思（用户指令立单 2026-10-15）

**场景**：`plan run/advance --task <文件>` 的任务书文件格式（目标/输入/交付/白名单/
验收预期）与存放命名约定（`orchestration/state/plans/<plan>-<step>.task.md`）无任何
文档，只存在于历史文件里；组长每次都要先翻旧任务书反推模板。

**证据（复现 → 实际 → 期望）**：
- 复现：写 I.i2 任务书前搜「任务书模板」——command-surface.md 对 `--task` 只有一行
  「任务书文件」；SKILL「铁律 5」只讲**内容要求**（自包含：目标/路径/交付/白名单/
  验收预期）不给**格式与落点**。
- 实际：读 `orchestration/state/plans/tb-2-exp-20261015-s1.task.md` 反推出
  `# 任务书 <plan> · <step>：<标题>` + 五段结构；文件位置与命名靠样例观察，未知是否
  正式约定。
- 期望：文档给出任务书模板 + 放放/命名约定（或声明位置随意、--task 只读内容），一次查到。

**建议**：在 dispatch-playbook（或 command-surface `--task` 行展开）补：①任务书 md
模板（标题行 + 目标/输入（只读）/交付/白名单/验收预期 五段）②存放命名约定
`orchestration/state/plans/<plan>-<step>.task.md`（若正式化）③`plan run/advance` 的
[NEXT] 在接收 `--task` 时顺带提示模板位置（一行即可）。

success_criteria:
- 技能文档内存在任务书模板（五段结构与铁律 5 的「自包含」要求一一对应）；存放命名
  约定明确（正式化或明示无要求）。
- 新组长按文档可直接写出合规任务书，无需读历史样例。
