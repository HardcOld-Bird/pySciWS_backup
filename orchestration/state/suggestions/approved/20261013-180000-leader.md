# 改进建议（leader，待审批）

**（带宽治理 A，前置）provider 报错原文入台账 + 失败三分类器（bandwidth/outage/quota）**

kind: usability
success_criteria: 见文末。背景（用户 2026-10-13）：mimo 明确 10 RPM / 10M TPM；
所有提供商并发带宽限制与项目需求同量级，不能视作"足够"。区分「带宽不足」与
「渠道真不可用」是一切延期/回退策略的前置——而**当前台账只存 stop_reason 短码，
provider 报错原文根本没入账**（本次实测），分类器无原料。

规格：
1. **报错原文入台账**：dispatch 失败路径把 provider 原文（会话 jsonl 末条
   synthetic/error 文本，或 envelope result/stderr，截 2000 字符）写入
   deliveries.jsonl 新字段 `error_text`；成功跳不写；
2. **共享分类器** `classify_failure(error_text, stop_reason, is_error) -> str`：
   - `bandwidth`（限流/并发/带宽簇：rate、concurrency、TPM/RPM、429、
     "retry later"、"please retry"…）；
   - `outage`（auth、model/endpoint not found、5xx、连接拒绝…）；
   - `quota`（沿既有 credit-usage 文案表）；
   - `unknown`（无匹配）；
   关键词表落**可配置面**（`state/failure-classes.json`，仿 failure-tags.json
   纪律：增补附定义；devops 可扩，改后全链生效）；
3. **语料种子**：实现时从近 12 个会话 jsonl 采真实样本（已见 mimo
   "Custom model service error, please retry later…"、`<synthetic>` 空
   stop_sequence 等）落表，并各钉一条回归样例；
4. 既有 `_detect_quota_exhaustion` / channel_error 识别**重构为分类器调用**
   （单一真源，行为不回归）。

success_criteria：
- 台账含 error_text（构造失败跳实测）；分类器用真实样本+边界样例单测全绿
  （bandwidth/outage/quota/unknown 各 ≥2 例）；既有 quota/channel 识别行为
  回归不变（原用例照绿）；全量无回归。
