# 改进建议（leader，待审批）

**（E0-A，REFACTOR v1.0 §12）决策日志启动 + reject 强制 override 留痕**

kind: usability
背景：`orchestration/REFACTOR.md`（v1.0 定稿，用户终审通过）E0 阶段判据 1–3。
决策日志是 twin 训练与 override 审计的原料层，必须最先落地。

规格：
1. 新建 `orchestration/state/preference-journal.jsonl`，行 schema：
   `{"ts","situation","options","choice","reason","source","kind"}`（REFACTOR §11）。
2. 回灌存量：解析 README §13 裁决记录表，每行一条 journal 记录
   （source="backfill-readme13"，kind="ruling"，situation/choice 取表格原文摘要，
   reason 可空）。回灌为一次性脚本或手动生成均可，脚本放 bench 不落 src。
3. `orch reject` 硬化：无判决依据的否决（当前即一切 reject）必须附
   `--override "<详细理由>"`，缺失 → 非零退出 + 可读提示；提供 → 正常否决并
   自动追加 journal 行（source="override"，situation=建议摘要，reason=理由）。
   approve 侧本轮不动（判决包 E5 才实装）。
4. orchestration 技能真本同步一句 reject 纪律（≤8KB 预算内）。

success_criteria（E0 判据 2、3）：
- `wc -l orchestration/state/preference-journal.jsonl` ≥ README §13 裁决条目数；
- `orch reject <id>`（无 --override）非零退出且提示含「--override」；
- `orch reject <id> --override "测试理由"` 后 journal 末行 source=override 且理由完整。

注意：journal 文件应 git 跟踪（长期资产）；涉及 workflow.py 的改动须附阳性
测试用例（guards/CLI 面 fail-open 教训，见 20261010-193601 建议）。
