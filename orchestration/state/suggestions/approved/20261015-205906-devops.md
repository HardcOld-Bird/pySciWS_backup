# 改进建议（devops，待审批）

kind: usability
delivery: leader-reflection
来源：组长工作摩擦反思（用户指令立单 2026-10-15，第二轮）

**场景**：JOB-DONE 事件不携带交付全文留档路径。组长若想在 `plan advance`（结算+派发）
之前先读完整交付把关（例如据此书写下一环节任务书），只能自行找文件。

**证据（复现 → 实际 → 期望）**：
- 复现：JOB-DONE 唤醒行只给「devops job 收尾：done（result）｜建议处置：orch events
  drain → orch plan advance」；grep `state/deliveries` 于技能文档与 README —— **零命中**。
- 实际：为读 I.i2 完整交付，先猜 `orchestration/pods/devops/outbox/`（旧面，最新件停在
  19:40 的 `delivery-*.xml`）→ 再查 ledger（只有台账行无路径）→ 最后
  `find -newermt` 才定位 `orchestration/state/deliveries/<job-id>.md`（3 轮额外查找）。
  而 `plan advance` 结算输出里其实有「交付全文留档：<path>」一行——信息存在，只是在
  「先读交付、后 advance」的时序下拿不到。
- 期望：事件面直接给出交付留档路径（advance 已有该行，把同一信息前移即可）。

**建议**：
1. JOB-DONE 事件消息（watch 注入的路由卡同源）尾附「交付全文留档：<path>」一行；
2. 或 `events drain` 明细对 JOB-DONE 条目展开该路径；
3. 顺带在 command-surface「归档与成本」段注明 `orchestration/state/deliveries/<job-id>.md`
   为交付全文留档的规范路径（当前零文档）。

success_criteria:
- 任一成员 job 完成后，不运行 `plan advance` 即可从事件面（watch 唤醒行或 events drain
  输出）拿到交付留档绝对路径并成功读取；
- `state/deliveries` 规范路径在技能文档有一处注明。
