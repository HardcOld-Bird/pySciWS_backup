# 改进建议（leader，待审批）

**（E5b，REFACTOR v1.0 §5.1/§5.6）组长判决包流：审批强制 J/M/J+M/override 四态 + 交付后核验闭环 + 咨询环节**

kind: usability
success_criteria: 见文末。依赖：E4（M 选项需 bench 队列）、E3-prep（J 已
就位）。授权：REFACTOR v1.0 定稿 + 用户确认 jury-brief 直通规则。

规格：
1. `orch approve <id>` 改为判决包强制参数：`--jury`（阻塞仲裁，复用共享库）、
   `--bench <case-spec>`（approve+基线捕获+实施后 A/B 入 bench 队列）、
   `--jury --bench`（双，实测覆盖仲裁）、或 `--override "<理由>"`（四者必居
   其一，否则拒绝——代码硬保证）。**例外通道**：缺陷类且当条交付含 blocked
   （in-vivo 实测即依据）→ 现行为（直接 approve 写任务书）保留，拒绝走
   override；规程注记「建议连带 --bench 复跑原失败案」。
2. jury 裁决 reject → 自动落驳回（组长只写回复）；approve → 入 backlog +
   唤醒 drain（现有链路）。
3. §5.6 交付后核验：条目带 `--bench` 者，devops 合并后**自动**生成 bench 队列
   项（实施后副本+对比），判决改善→销账、未改善→自动立案纠正提案
   （source=post-verify，新案卷进正常判决流）；inconclusive→挂起呈组长
   （twin 终裁接线等 E6 全量，本期留 escalate 标记）。
4. 咨询子命令：`orch consult-twin <case>`（taste_enabled=false 时明确拒绝并
   提示待上线——接口先就位）、`orch consult` 保持 deputy 面；inspector 侧
   同名能力经共享库入 pysci-inspect（§0.9）。
5. status 增「判决包健康」段：各判决通道用量、override 率、escalate 积压。
6. charter/技能真本同步新审批规程（≤8KB）。

success_criteria：
- 无判决包参数 approve 被拒（非零+提示）；缺陷+blocked 例外通道实测保留；
- 一次真实提案走 `--jury --bench` 全程：仲裁放行→实施→自动 bench→二元
  判决→销账；构造未改善案→自动立案纠正提案；
- override 率入 status；consult-twin 未启用态拒绝实锤；全量无回归。
