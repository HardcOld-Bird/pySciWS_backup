# 改进建议（leader，待审批）

**（缺陷类）BYOK 渠道级故障（"Custom model service error"）不在系统性失败识别面：不触发回退换档与全局停止，队列连续空烧**

kind: defect
证据（2026-10-12 实测，devops 会话 6f0cc8e5 jsonl）：
- 失败形态：assistant 消息 `model="<synthetic>"`、`stop_reason=stop_sequence`、
  `stop_sequence=""`、正文固定句 `Custom model service error, please retry
  later or switch to another model.`；
- 现行模式表（dispatch.py:47）`credit usage limit|out of credits?|insufficient
  credits?` 零命中 → 不走 quota 换档回退、不触发 drain 全局停止；被归
  run_failed/stop_sequence → 自动重试一次再烧一轮 → 条目带伤推进；18:35-19:38
  连烧 #68/#69/#70/#71 四单（E6b 双 needs_leader）；
- 定性：渠道级系统性故障（余额/服务面），与 quota 同族——整条渠道不可用，
  重试与换单同样无益。

修复面：
1. 模式表扩充**渠道级失败**类（建议独立 kind=`channel_error`，别混 quota
   文案）：`custom model service error|please retry later or switch to
   another model` + `model=="<synthetic>"` + 空 stop_sequence 三特征合取，
   防误伤可自愈故障（沿 2026-10-10 宽匹配教训的谨慎基调）；
2. 处置同 quota 族：按档 `<tier>_fallback` 换档重试一次；仍败 →
   drain 全局停止（`.done stopped=channel_error`）+ watch 事件
   `CHANNEL-STOP`（QUOTA-STOP 同形），条目保持 pending 不烧账；
3. status 提醒行与 ledger error 文案区分 quota/channel 两类；
4. 阳性用例：注入 synthetic 三特征 envelope → 断言不重试原渠道、换档、
   全局停止、pending 不连坐四段。

success_criteria：用例全绿；下一次真实渠道故障（或充值前的空窗）表现为
一次 CHANNEL-STOP 而非逐单 needs_leader；既有 quota 路径不回归；全量无回归。
