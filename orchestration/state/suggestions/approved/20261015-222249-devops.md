# 改进建议（devops，待审批）

kind: usability
delivery: leader-reflection
来源：组长工作摩擦反思（2026-10-15 第三轮）

**场景**：任务书白名单「声明即注入」机制（backlog 20261015-132939-fix3 的修复）只写在
`dispatch.py` 的函数 docstring 里，技能面无一字；且解析失败会**静默**丢写权（组员开工
即被 pod-guard 拦），派发时无告警。

**证据（复现 → 实际 → 期望）**：
- 复现：f1 派发后发现 plan step dirs 只有 1 个目录、任务书白名单段多声明了 1 个（scripts），
  担心写权不一致——grep 技能文档（SKILL/command-surface/dispatch-playbook）无
  「声明即注入」口径，最终读 `dispatch.py:365-385` 源码才确认「任务书白名单段声明即
  注入，与 --dirs/plan dirs 取并集」。
- 实际：机制正确但不可见；且 `_whitelist_entries` 若解析不出目录（格式微调即失配），
  注入侧静默得空集，组员到写文件才发现 `whitelist_conflict`。
- 期望：①派发要领一处明示该机制（任务书白名单=声明即注入、与 plan dirs 并集）；
  ②任务书白名单段解析出 0 目录且 plan dirs 非空时，派发输出显式告警。

**建议**：
1. dispatch-playbook「白名单最小化」节补一句「任务书『白名单』段声明即注入
   （PYSCI_TASK_DIRS 与 --dirs/plan dirs 并集）」；`plan advance` 交接决策点的
   「白名单建议」行同处可加半句「（任务书声明即注入，可扩展）」；
2. `taskbook_whitelist_dirs()` 解析结果为 0 而 dirs 非空（或反之任务书声明了但解析
   丢空）时，派发日志/输出出 `[!] 任务书白名单段未解析出目录（格式？）`——把静默
   失败升级为可见失败。

success_criteria:
- 技能文档 grep「声明即注入」命中 ≥1（含并集语义）；
- 构造白名单段格式失配的任务书，派发输出出现显式告警（回归测试断言告警行）；
- 正常任务书派发无新告警，全量绿。
