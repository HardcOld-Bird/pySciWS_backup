# 改进建议（devops，待审批）

kind: usability

**主题**：任务书要求的「合并前 git status 交集检查」缺可执行判据，`main..HEAD` 形式在分支落后 main 时必然误报

kind: usability

**场景（本会话与上一会话各实发一次）**：任务书写「合并前 `git status` 检查——若 main 工作区存在**会被本次合并触碰的**未提交改动即 `<blocked>`」。要算「本次合并触碰哪些文件」，直觉写法是 `git diff --name-only main..HEAD`，但分支基线落后 main 时它列出的是**别人新提交的**文件：本次实测 `main..HEAD` = 8 文件，其中 `orchestration/state/backlog.json`、`orchestration/state/registry.json` 我一次都没提交（main 前进了 `80ce9ef`/`fad4699` 两次），`comm -12` 与 main 脏 backlog.json 求交 → **假阳性交集**，`git merge-tree` 实际 rc=0。上一轮 P0 之所以走 `<blocked>`，真交集项（registry.json）也来自这种「双向 diff」读数，我多花一轮去分辨「是我改的」还是「是 main 领先」。

**期望**：把误报面消掉——按 merge-base 起算的**本次提交面**才是合并会触碰的文件。

success_criteria：二选一并落成机械面：(a) 任务书模板/技能真本「worktree 作业规程」里把判据写死为 `git diff --name-only "$(git merge-base main HEAD)"..HEAD`（或 `git show --name-only` 逐 commit），并注一句「`main..HEAD` 在分支落后时含别人的提交，不可用作交集」；(b) `pysci-dev worktree merge` 内建该检查——merge 前自取本次提交面与 main 脏项求交，非空即打印冲突文件清单并 rc=2（工具比规程条文更防漏，且顺带替组长挡住「合并覆盖未提交工作」）。

期望改动面：`orchestration/skills/devops/SKILL.md` §worktree 作业规程（注意该文件现 8178 B，需等量压缩或把细节进 `references/`）或 `src/pysci/skills/devops/tools/dev.py::cmd_worktree_merge` 一处。
