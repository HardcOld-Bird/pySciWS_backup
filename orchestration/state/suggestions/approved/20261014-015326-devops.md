现象：orchestration 工具里可注入的**测试缝**（`_sleep`/`_spawn_detached`/`next_defer_s` 等）若用 `from .drain import _sleep` 绑定，测试对 `drain._sleep` 的 monkeypatch **打不到**调用点——conftest 的 autouse「睡成 no-op」形同虚设。M6 实测踩到：成员 worker 的「睡到最近到期」循环在 no-op 睡 + 未推进的 `next_defer_s` 下会**死循环**（真跑测试会挂死），我改走 `_drain._sleep` 模块属性访问才被 autouse 覆盖。
建议：orchestration tools 里凡「测试会 monkeypatch 的注入缝」，统一经**模块属性**调用（`drain._sleep(...)`），不经 `from ... import name` 值绑定；同类缝包括 `_sleep`/`_spawn_detached`/`next_defer_s`。可在 charter/技能里落一句，或用一条回归测试钉住。
success_criteria：
- 存在一条测试：patch `drain._sleep`（no-op）后跑一个会进入「睡到到期」分支的 worker，断言其**未真睡且未挂死**（当前 from-import 绑定会漏过该 patch → 真睡/挂死）。
- 可证伪：若该测试在现树（或未来某次把 `_sleep` 改回 from-import 的改动）下超时/失败，则本条未生效或已回退。
