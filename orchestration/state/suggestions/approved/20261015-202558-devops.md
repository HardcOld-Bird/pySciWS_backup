# 改进建议（devops，待审批）

kind: usability
delivery: leader-reflection
来源：组长工作摩擦反思（用户指令立单 2026-10-15）

**场景**：拆解大任务写 plan YAML 时，字段语义（kind/evidence_sections/role/gate_jury/
read 标记等）没有单一权威速查，须跨多处拼凑，且 README 的引用路径断链。

**证据（复现 → 实际 → 期望）**：
- 复现：为 tb-3 拆解查「plan YAML 字段表」——grep `plan-decomposition.md`（只有拆解
  方法学，无字段表）→ 读 `orchestration/README.md` §4.2（摘要，尾注「全量见
  references/plan-and-routing.md」）→ 在技能 `.qoder/skills/orchestration/references/`
  下找该文件 `grep: No such file or directory`（实际在 `orchestration/references/`，
  README 语境与技能 references 目录指法不一致）→ 最终靠历史样例
  （rework-tb-20261015-091655-1.plan.yaml、tb-2-exp-20261015.plan.yaml）反推字段。
- 实际：约 4~5 轮工具调用才凑齐；`read: plan-decomposition.md` 标记的触发条件只在
  plan-decomposition 末尾一句；`review`/`role` 的合法值靠猜。
- 期望：一处「plan YAML 字段表」（每字段：含义/合法值/何时用/出处示例），README §4.2
  与 SKILL「命令面」都能一跳到达。

**建议**：在 `plan-decomposition.md` 附字段速查表（或在 command-surface 单列一节）：
id/goal/read/steps[] 递归（superstep mode: serial|parallel + children）与叶子
{member, brief, dirs, effort, kind: self, evidence_sections, role, gate_jury,
review}；并把 README §4.2 尾注的引用路径改到可达位置（或注明「在
orchestration/references/」）。

success_criteria:
- 从 SKILL.md 或 README §4.2 出发一跳内能读到字段表；字段表覆盖上列全部字段与
  `read:` 标记触发条件。
- README §4.2 尾注引用的文件路径实测可打开。
