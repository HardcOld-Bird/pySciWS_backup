# 改进建议（leader，待审批）

**（inspector v2，用户设计 2026-10-13）会话记录审计：transcript 工具链（list/scan/fetch）+ 三态游标 + 优先级调度**

kind: usability
success_criteria: 见文末。背景：用户设计+组长细化并确认（聊记录=inspector 主战场；
现有 transcript-audit 菜单项为"随机盲读"，升级为工具链驱动的摘要先行、锚点深挖）。
**纯 agent 导向**：不设面向人类的阅读形态（用户查聊天用 Qoder CLI 本身）；CLI 返回值
即阅读面，落盘文件只是缓存。

## 规格

### 1. 共享库 + CLI（inspector 侧）
- `src/pysci/skills/orchestration/tools/transcript.py`（共享库）+
  `pysci-inspect transcript list|scan|fetch`（inspector 专属 CLI 扩展）：
  - `list`：扫描 `~/.qoder-cn/projects/*/`，**按优先级**输出可检会话
    （leader 会话 > 组员；新 > 旧）；含 sid、项目键、回合数、最后活跃时间；
  - `scan <sid> [--turns a-b]`：输出**简版**——过滤 `<synthetic>`/attachment
    等注入噪声，思考与工具调用折叠为单行（`[thinking]`/`[tool: name, size]`），
    只留 user 消息与 assistant 正式回复；**每回合一行索引**（id/时间戳/
    user 首段/assistant 首段/字节量）+ 行锚；超长正文截断并标注实际大小；
  - `fetch --anchor <sid:L_a-L_b>`（或 `--grep`）：从原始 jsonl 精确取段渲染，
    **有界返回**（工具结果截断+大小标注）——零盲读、字节级定位。
- 回合定义（用户确认）：一位 user 记录 + 其后至下一 user 前的 assistant/工具段 = 一回合。
- 行锚：`src: <sid>.jsonl:L<a>-L<b>`；findings 的 `--repro` 可直接引锚
  （比转述更可复现；用户已确认会话内容可原样引用）。

### 2. 三态游标（`state/inspector/transcript-cursor.json`）
- 每会话 `{project, sid, rounds_seen, last_round_ts, checked_at}`；
- **可检查** = 回合数≥5 且未检过（首次达 5 即转可检）；
- 检查后 → **已检查**；
- 重可检：新增回合 ≥5；**或**每有新回合刷新 2h 静止计时器，计时到点且期间
  新增≥1 回合（会话静止 2h）→ 无条件重可检；
- 短于 5 回合且未静止：不检查。

### 3. 调度与预算
- 每轮巡检 digest/scan **≤3 个会话**（用户确认），按优先级取头部；
- digests/扫描缓存落 `state/inspector/**`（gitignored 运行态），保留最近 N 期
  自动清理。

### 4. 菜单改造
- `transcript-audit` 的 brief 改写为工具链工作流：`list` → 选靶 → `scan` 简版
  定位疑点 → 按需 `fetch` 深挖 → 发现落台账（repro=行锚）；
- 与设计审查 rubric/诚实条款审计的既有面衔接不变。

success_criteria：
- 三态判定状态机单测矩阵（首达5可检/检查后已检/新增5重可检/静止2h重可检/
  短会不可检/持续活跃不误判）全绿；
- 优先级实测：构造 leader 与 pod 会话混合样本 → list 排序正确（leader 先、
  新先）；
- 一次真实巡检全链：list→scan→fetch 完成核查，finding 的 repro 引行锚且
  他人按锚可复现；单轮 ≤3 会话预算实测；
- 注入噪声（synthetic/attachment）在简版中被过滤；超长工具结果截断+大小
  标注实测；缓存目录 gitignored 且清理有效；全量无回归。
