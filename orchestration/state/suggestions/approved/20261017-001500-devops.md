# PENDING-WORK 事件积压报警无法区分「已处理未销账」与「真没人处理」，文案误导

kind: usability
source: leader
fingerprint: pending-work-ack-vs-unhandled-20261017

## 现象（实证，2026-10-16/17 通宵反复出现）

统一事件流的消费账是两段式：watch 唤醒（叫人）≠ `events drain` 销账（盖章）。组长被唤醒后常已把事件**处理完毕**（读交付留档、验收、推进下一环节）但未销账，30 分钟后巡更即报：

```
PENDING-WORK 队列非空 —— 有活却没人干：统一事件流 1 条超 30min 未排空
```

「**有活却没人干**」在该场景下是**错怪**——活已干完，欠的只是账面（ack_seq 未推）。实证多起：JOB-DONE 事件经唤醒通知处理后（交付留档已读、plan 已推进、backlog 已销），仍触发该报警逼出一轮纯记账性唤醒。报警本意（autonomy-fix a1「不许静默积压」）是兜底防漏唤，**兜底必要，但应与「真积压」区分**。

success_criteria:
- 巡更对 `events.unacked()` 超时项做**旁证细分**后再定性：`JOB-DONE/STEP-REVIEW-DONE` 类事件若其 subject 对应的交付留档已存在、或对应 plan 环节/队列条目已终态（旁证任一成立即「疑已处理」），文案改「**已处理疑未销账**（请 `orch events drain` 盖章）」且**不进 PENDING-WORK 唤醒**（降级为 status 注记）；旁证不成立或事件类型无旁证可查（如 NEEDS-LEADER）维持现唤醒；
- 文案「有活却没人干」只保留给「无旁证/旁证不成立」的真积压；
- 测试：构造「已处理未销账」断言不触发 PENDING-WORK 唤醒（status 仍注记）；构造「真未处理」断言照常唤醒；两类同刻并存各归各位；
- `uv run --no-sync pytest tests` 全绿。
