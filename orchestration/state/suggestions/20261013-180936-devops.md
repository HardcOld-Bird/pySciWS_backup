# 改进建议（devops，待审批）

kind: usability
delivery: result

kind: usabulity

场景：`orchestration/README.md` §13 裁决表已有「边界避让派发」行，但**只记实现、不记测试面**。本次续作恰恰因此多烧一跳——143000 那跳的交付只列了种子 id，菜单项的实现虽随同批合入 main，条目却仍 pending 被重派；重派的任务书读起来像是「从头做一遍」，而真实缺口只是 12 例测试。

易错点：销账口径（`<result>` 里的 `backlog id=`）与实际合入面（同一 worktree 里的菜单项）可以分离。实现进了 main 但 id 没列 → 条目 pending 但代码已在 → 重派后组员要先花一跳搞清楚「到底还缺什么」，否则容易重复实现或空转。

期望形态：批量菜单的交付提示里显式一句「菜单项与种子同批合入时，**每个已实施的 id 都要列**，未列即视为未销账、会重派」；或 drain 在重派前比对「该 id 的实现是否已在 HEAD」，已在则任务书改写成「补齐剩余面（测试/文档）」而非复述原规格。

success_criteria: 批量菜单类任务书含上述销账口径提示；或 drain 重派时对「实现已在 HEAD」的条目自动改写任务书为补缺形态。
