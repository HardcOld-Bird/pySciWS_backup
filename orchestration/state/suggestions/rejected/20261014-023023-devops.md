# 改进建议（devops，待审批）

kind: usability
delivery: result

kind: usability
现象：`orchestration` 与 `devops` 技能的 `SKILL.md` 均已贴 8KB 硬顶（本次实测 8179/8182 B）。后果是**加一条命令或一句约定，必须先删既有正文**——M7 与本次连续两跳都踩到；更实际的次生成本是：leader 指定的文档落点（如本次「编排技能/charter 一句」）会因贴顶而落不下去，实施者只能自行改落到别处（本次落进 devops `references/lessons-incidents.md`）。
建议：给这两个 SKILL.md 做一次**结构性拆分**——命令面/机制细节移入 `references/*.md`（如 `commands.md`、`conventions.md`），SKILL.md 只留「决策与调用面 + 一行索引」，把常驻正文降到 ≤7KB，留出增长余量。拆法遵循 basic.md §1「超出预算说明该设计过于复杂——正确反应是重新设计使用方式或拆分」。
success_criteria：
- orchestration 与 devops 的 `SKILL.md` 各 ≤7KB，且各自有明确的「细节在 references/」边界（命令细节/约定不在 SKILL.md 展开）。
- 可证伪：下一次给这两个 SKILL.md 之一加一条命令或一句约定时，**无需删除既有正文**即可通过 8192B 门禁；若仍需删正文才能过，则本条未生效。
