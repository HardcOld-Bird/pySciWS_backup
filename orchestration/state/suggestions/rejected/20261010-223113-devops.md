**20261010-221018-devops-B：运行态文件的跨合并搬运缺机械化（本次人工搬）**

`--no-ff` 合并把 registry.json 从「带 sessions」变为「不带 sessions」，但运行态文件本身在 gitignore 面、不随合并 transfer。若目标机（本例 main 工作区）不存在 `sessions-runtime.json`，合并后 `Registry.load()` 会走「配置无内嵌 sessions + 运行态缺席 → 无迁移可触发 → 运行态内存空」分支，导致**旧会话池丢失**。本例已在合并后手工 cp worktree 的 `sessions-runtime.json` 与 `registry.presplit.json` 到 main 磁盘，才保住了 figure/devops/reviewer/deputy/lit 5 位成员 6 条会话记录。

机械化候选（择一）：
- (a) **dispatch 前哨兵**：`Registry.load()` 后若 config 无内嵌 sessions 且 runtime 缺席，从 backup 或 config HEAD 反推——但语义不干净（HEAD 也可能已迁过）。
- (b) **merge 前一次性 pre-hook**：把「cp 运行态 + 备份」写进 worktree 合并脚本或 `pysci-dev worktree remove --merge <id>`——但 devops 不用 orch，工具面归 pysci-dev。建议扩 `pysci-dev worktree merge <id>` 子命令（现无），合并前扫 worktree gitignored state 文件（sessions-runtime.json、registry.presplit.json、watch.json、skills-deployed.json 若漂移等）→ 复制到 main 同名位置；纯 cp、无冲突语义（同名覆盖即可，因为 main 侧本就不该有——它由旧代码心跳写在 registry.json 里，本次才拆出来）。
- (c) 更轻：**devops 技能/charter 纪律端**加一行「涉及 state 运行态文件的合并交付，交付前手工 cp gitignored 面从 worktree 到 main」——把知识固化在文档，工具不扩面。

我倾向 (c)+(a) 混合：纪律端先落地（技能已写；补一句到 registry-runtime.md「排查提示」段即可）；工具端 (b) 值得但优先级低于 (c)。请组长裁决。
