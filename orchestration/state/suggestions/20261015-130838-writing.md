**缺陷：任务书「白名单（写权限）」段不注入 pod-guard 的 `PYSCI_TASK_DIRS`，导致白名单目录内写入被误拦。**

- 现象：`<blocked tags="whitelist_conflict">`——任务书声明了白名单目录，派发 job 的 `dirs` 却为空，pod-guard 把该目录判为「白名单之外」。
- 复现命令：
  ```
  cd orchestration/pods/writing
  printf '%s' '{"tool_input":{"file_path":"<项目根>\\data\\大任务\\1_文档阅读与需关注事项总结\\0_待关注事项总结.md"}}' | node ../../guards/pod-guard.mjs; echo "EXIT=$?"
  ```
- 实际输出：`pod-guard: 拦截对 …的写入——目标在 pod 与本任务白名单目录之外。`，`EXIT=2`。
- 期望输出：目标在任务书白名单内 → `EXIT=0`（放行）。
- 定位线索：`PYSCI_TASK_DIRS` 仅由 `runner.build_env(task_dirs=…)` ← `queueworker` 读 `item["dirs"]` ← 派发时 `--dirs` 传入（`orch.py:494/658`）。本单 `orchestration/state/queues/writing.json:11` = `"dirs": []`，plan YAML 步骤 b2 无 `dirs`。而任务书 `## 白名单` 段目前**只被 dispatch lint 用**（`dispatch._whitelist_entries` → `_whitelist_warning`），**不产出** `task_dirs`。
- 期望形态（择一）：① 派发时解析任务书 `## 白名单` 段自动并入 `dirs`；② 派发口校验「任务书写了白名单段但 `dirs` 为空」时告警 / 提示补 `--dirs`。
- 附加小问题：`_whitelist_entries` 的路径样正则 `[A-Za-z0-9_./\-*]+` 不含中文，`data/大任务/…` 这类**含中文的白名单条目会被整条丢弃**（当前条目就以 `- data/大任务/…` 起首，解析不出）。建议一并放宽以支持中文路径。
- success_criteria: 任务书 `## 白名单（写权限）` 段声明的目录（含中文路径条目）能被派发侧解析并注入 `PYSCI_TASK_DIRS`，使组员对白名单目录的 `Write/Edit` 放行（`EXIT=0`）；且「声明了白名单段但 dirs 为空」在派发口可见告警。
