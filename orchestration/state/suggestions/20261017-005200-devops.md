# argparse 报错串仍暴露 5 个内部命令名：改走 main() 前置分流收干净

kind: usability
source: leader
fingerprint: argparse-internal-names-in-error-20261017

## 现象（实测原文，2026-10-17）

命令面整备（`20261016-221800`，merge `f8076d0`）已把 5 个内部命令从 usage/帮助隐藏，但**报错串仍列它们**。实测 `pysci-orch bench-up`（旧名）输出尾部：

```
error: argument {status,plan,…,bench,inspector}: invalid choice: 'bench-up' (choose from 'status', …, '_watchdog-loop', '_queue-worker', …, '_drain-devops', '_bench-worker', '_inspect-worker')
```

`choose from …` 列表含 5 个 `_` 内部命令名。221800 交付已如实上报成因：argparse `_check_value` 用的 `_name_parser_map` 与 `choices` 是同一对象，直接隐藏会**同时废掉内部命令的调用**（钩子 `watch-arm.sh`、watchdog 派生都在调），故只收了 usage/帮助两面版面。影响纯观感（无功能/安全问题）。

## success_criteria:

- 任何错误输入/旧命令名的报错串 **不含 `_` 前缀内部命令名**（测试以运行期拼接禁词断言报错文本零命中）；
- 5 个内部命令**照常可调用**（`orch _queue-worker -h`/`orch _watchdog-loop` 等解析正常；钩子调用面回归测试绿）；
- usage/帮助维持 221800 现状（内部命令继续隐藏）；建议实现路径按其交付注记：`main()` 前置分流到独立内部 parser（公开 parser 的 choices 不含内部名），或等价方案，实施自由；
- `uv run --no-sync pytest tests` 全绿。
