标题：drain 孤儿回收只看条目 started_at/锁旧否，不验 worker 进程是否仍活，导致「同一 backlog 双 worker + 同一 worktree 并发写」
场景：本单 18:11:04 派发（pid 19132），因上下文压缩/长勘察被 18:28:10 的 drain 判为孤儿；回收拆掉 worktree 与分支后**未终止旧进程**，随即新派发 pid 22256。两者共用任务书要求的同名隔离面（`pysci-dev worktree add <entry-id>`），旧会话写操作全部落空、新会话在同一目录重建并写入 255 行——两套实现叠影，谁也验收不了。
证据：`orchestration/state/devops-runs/20261012-182808.log` 四行原文；`git reflog show wt-20261012-164600-leader`（18:29:30 branch: Created from HEAD）；`Get-CimInstance Win32_Process` 两行 qoderclicn.exe（19132/22256 同活）；worktree `git status --short` 显示 registry.py+jury.py 被非本会话写入。
success_criteria: 回收 in_progress 孤儿条目时先判活（`_lock_live`/worker pid 仍在进程表即不回收，或回收前先终止该 pid 并确认退出）；若仍回收，须把 worktree/分支改名到本次 run 独占（例如 `<entry-id>-<run-ts>`）后再派发，使任何两个 worker 不可能共享同一隔离面。阳性测试：造一个「锁主 pid 仍活但条目被标 stale」的夹具，断言 `drain` 不产生第二个同 entry worker，且新旧 worktree 路径必不重合。
