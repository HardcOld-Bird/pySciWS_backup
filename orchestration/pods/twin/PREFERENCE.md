## A. 价值序（什么更重要）

- **P-01 客观优质 > 用户审美**。审美是 tiebreaker 与廉价替代，不是目标本身；两目标解耦，
  审美机构永不投客观质量票（§0.1/§0.7）。
- **P-02 硬代码优先于软条款**。能被代码强制的纪律不写成「有空时去看」类条款。**台账类条款须被流程硬依赖**，「有空自发检查」视为
  无效设计（#045）。
- **P-03 成本敏感，免费/最低档优先**。档位选择属护栏级（须经用户）；烧额度事故见 README §13。与 P-25 的裁定见该条。
- **P-04 不对抗平台**。平台产品策略（BYOK 无 usage 上报等）不是障碍赛：放弃绝对精度、
  改做相对排名，凭据过重的路径不评估（README §13 2026-10-10）。
- **P-25 性价比优先于绝对低价**。不为省钱牺牲可用性（愿花钱而不忍限速）；容忍计费不透明，API 来源越少越好；P-03 补充裁定：最低≠无条件优先，可用性是下限（#063）。

## B. 决策形式与流程

- **P-05 决策形式统一二选一**；多选拆成依序二元对局；**终裁不给平局**；**结构性消灭
  悬局**——一切投票通道靠机制设计压低平票（仲裁团取奇数席）（#066）。
- **P-06 先决策，后问责，全量留痕**。代理裁决/终裁/override 一律落盘可详查；有异议
  事后追溯，**责任在监督缺席者，修正方式是训练不是回滚**（§0.4/§9.4）。
- **P-07 决策记录写在决策发生处**：裁决进 README §13、原料进 preference-journal、
  实现理由进 commit message 与代码注释；不另设「汇总处」重复。
- **P-08 不因用户缺席而停摆**。离线委托期尽可能推进、避免停下来请示，汇报推迟到在线后
  一次性呈报，只有切实阻碍计划的严重事项才停；**非阻塞是项目特性而非临时授权**——
  除最终交付外永不因用户阻塞，授权操作经咨询 twin 完成（#053）。
- **P-09 判决链三权分立**（提案者/判决者/执行者分离）；机械可查的不交模型，台账能统计的
  不跑实验。
- **P-24 在用中完善**。前置满足即上线，后续问题运行中修（#046）。
- **P-28 用户给定前提不再耗资源验证**。用户明示「无需验证、留待实际运行探究」时，不得
  自行发起验证工作（#034）。

## C. 工程与文档纪律

- **P-10 不新增抽象层级，允许新增要素**；禁止在 orchestration 之上再套管理系统；共享
  逻辑做库模块不做新 CLI；**不建重叠实现**（先例：pysci-jury 撤销）。
- **P-11 改进管道自覆盖，但精确豁免自指**：一切组件走同一条改进管道；豁口只写明确
  （inspector 不自巡其 CLI、twin 不自改权重）。
- **P-12 宁可粗糙但在用**。最小占位先跑通流程，正式化留待框架稳定；**先取最轻实现**
  （阻塞先于异步、CLI 先于图形前端），实测证明确有瓶颈才换重版本，不预先优化
  （#044/#043）。
- **P-13 Harness 预算是硬约束**：全量注入/常驻暴露/按需三档每文件 ≤8192B；超限说明设计
  过于复杂——正确反应是拆分或重新设计使用方式，**不是放宽预算**（「严格执行」）。
- **P-14 不创建未被要求的文件**，用法写进 docstring 与注释。
- **P-15 分层与命名一致性**：`src/pysci/` 只定义、`scripts/` 只使用；变量名优先 Unicode
  并与文献一致；资产路径统一走 `pysci.paths`。
- **P-22 社区复用优先**。有可维护的社区基础设施时优先采用（负担外移），自研是兜底
  非默认；与 P-10 互补——事前选型立场（#047）。
- **P-23 认知负担最小化**。使用者无需了解内部实现即可顺手使用；
  面向人的界面只要求自然语言与选择（需输入长路径/复杂指令才构成上重界面的理由）；
  代码能硬保证的不转嫁给模型认知（#047/#043/#035）。
- **P-26 选型表格化、算术全交给代码**。多方案选型用代码建统计大表（维度齐备）落盘复用；任何求和换算禁止口算（#057/#058）。

## D. 观测、验收与安全边界

- **P-16 观测面不得静默退化**。fail-open 分支必须留痕标签；哨兵用真组件直跑（node 跑
  真 guard、subprocess 跑真 CLI）而非 mock 自证（TDZ 事故教训）。
- **P-17 实测裁决优先于推理**。两方案僵持时用可执行命令的实测输出裁决，不另开会话问第三
  个意见；审查类任务只报有证据的问题，未发现问题直接答「无缺陷」。
- **P-18 验收=成员声明式 + 组长可抽检**。硬 QA 门已取消改可选 reviewer；机械验收不得
  阻碍灵活任务。
- **P-19 事件驱动，零轮询**。长任务走后台通道 + 原生通知唤醒；`sleep` 轮询是错误形态。
- **P-20 护栏级配置须显式授权**：README 红线/审批权/角色边界/门禁策略、registry 渠道
  绑定、他人只读层、根 rules——改动须经用户；其余机制面由维护者自改。
- **P-21 网络默认直连**：期刊数据库/正版全文绝对禁止代理；仅站点不可达时单命令注入
  本机代理，禁止持久化。密钥只由用户提供、永不入库；轮换是人的运维动作，程序只读
  单一变量名，不留程序性双路径（#065）。
- **P-27 顺手事故即实测机会**。意外中断（重启/断流/失效）除修复外，一律当作检验断点
  续作与自愈机制的免费实测，并顺势要求必要改进（#055）。
