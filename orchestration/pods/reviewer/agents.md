## 审查经验（初始为空——工作中积累：领域基准、常见缺陷模式、对照文献线索）

- **图件审查路径**：Read `out/*_preview.png` 与主 png 做视觉判读 + 独立复跑
  `pysci-figures audit <figdir> --panels` 核验生产者自检声明（只读、低成本）；
  数据自洽可按 CSV 头声明的模型手算抽查。小间隙双向箭头标注的箭头头部易大于间隙本身
  而呈实心块状——美观度扣分点而非硬缺陷。
- 审查任务书仅给产物路径、不嵌原生产任务目标陈述；G2 判定须依赖生产者 notes.md 自述，
  独立性略欠（已 infra_suggestion 转呈）。
- **非 scaffold 综合图审查路径**：`Read` 整图 → 自建 PIL 裁剪脚本逐处放大（标题/colorbar/
  极坐标中心/行标签）→ 像素阈值扫描定位伪影与外部 logo → `pysci-figures doctor` +
  `audit`（非 scaffold 恒 N/A）。硬项取证：**H2** 用「CSV 列头 ↔ 生成脚本绘图表达式 ↔
  图面标注」三方对照（标题量纲与实绘制量/色标不符是高频缺陷）；**H3** 用黄像素扫描查
  外部渲染器 logo。反复出现的缺陷模式：标题量纲（模/实部）与色标不符、外部渲染器 logo
  随粘贴图带入、同行共色标致弱组被淹没。生成脚本 mtime 可能晚于图 → 硬判定优先采信
  「图面 + 数据」直接证据，脚本仅佐证。
- **工具核验**：`pysci-figures inspect <png>`（尺寸/色域占用/饱和像素占比/**边缘水印检测**）
  承接非 scaffold 产物核验，不必再全靠自建 PIL。
- **可复现性是 H5 最强证据**：`importlib` 载入生成脚本（不触发 `main()`）、把模块级
  输出路径改指本 pod 路径后调用绘图函数 → 与受审图逐像素 diff（位级同一），同时验证
  脚本与图同版本（比 mtime 可靠）。
- **物理预期输入机制**（任务书随附「物理预期」小节）**让 H1/D1 从 n/a 变为实判**——
  判据落在「图↔核验记录一致」而非「符合通则」；已知非理想结果须在任务书中连同证据出处
  预先声明为设计输入，否则极易误判物理 FAIL。
- **尺寸陷阱**：`savefig.bbox="tight"` 下自述的 mm 尺寸常是**裁切前画布**、成品实测更小；
  核尺寸一律以 `inspect`/元数据实测为准。
- **像素核验有效范式**：直径/弧线用近黑阈值 `max(RGB)<90` 反解 px/m，再逐列求最高彩色点
  验弧外溢；留白边带 8 px 扫描彩色像素计 logo；图形域外彩色像素须先排除设计上就在域外的
  插图元素，否则假阳性。
- **独立复核不复用既有缓存**——另起一张删文字版 + 放宽灰线掩码（lum<225，含反锯齿外缘）
  重求交，并加「最小距离」输出（交集 0 但余量很小的「贴线」风险，纯交集判法会漏掉）。
- **全图零遮挡扫描（基线无关）**：同脚本渲染「全文字 vs 文字置全透明（RGBA α=0）」两版
  （固定 bbox 使逐像素可比）→ 墨迹 = 差分 → 与黑线/灰线/彩色掩码求交。**必须用「置全透明」
  而非「清空字符串」（图例框随标签清空收缩 → 版面位移假交）也不是「文字改白」
  （文字压线处与白底同色 → 交集恒 0 假阴性）**；tight bbox 下两版尺寸会不同、无法比。
  脚本范式可覆盖标题/刻度/图例/脚注全图。
- **跨轮 diff 归属不可轻信**：历史「基线副本」版本不可考（实测与多目录产物同哈希）；
  改用「同脚本自对照 + H5 位级复现」的基线无关路径。
- **语义核验用脚本自身几何函数独立复算**（如点→框边最近距），不抄生产者说明。
